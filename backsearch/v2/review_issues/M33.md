# M33: best and level_code are not kept consistent: a split first node can store a level with best NULL, and a done node can store best with no level

verdict CONFIRMED, severity low, category bug
locations: jobs.js:698 (parseTree: summary optional for split nodes; done node may carry summary.best without level); finishJob; jobs.js:873 (bestOfExit requires level_code IS NOT NULL); exitSummary MAX(best) used by v2_finish

## Summary
parseTree makes the summary optional for a split node, so for the job's own node finishJob can store a valid level_code with best NULL. bestOfExit (ORDER BY best DESC) and MAX(best) then never see that level. It also accepts a done node with summary.best and no level. That best is invisible on every public page, because bestOfExit requires a level, but exitSummary's MAX(best) still makes it the published proof maximum, with no champion level behind it.

## Source report F88 (server-scheduling)
**A first node reported 'split' without a summary is accepted, and its level is stored with best NULL** at /Users/george/PathologyRecords/server/lib/jobs.js:698

*summary*: parseTree makes the summary optional for split nodes. For the job's own node, finishJob then stores best = NULL next to a valid level_code. bestOfExit (ORDER BY best DESC) and exitSummary MAX(best) never see that level.

*failure_scenario*: A client (or a future client change) sends {seed: J, status: 'split', level: {code, depth: 150}} with children and no summary. The report is accepted, but the 150-move level in J's explored part does not count toward the per-exit best, and no child re-explores that part. The current client always sends a summary, so this is latent.

*evidence*: 698: `} else if (n.summary != null || n.status === 'done') {` (split may omit the summary). 782-783: `finishJob.run(status, ..., s0 ? s0.best : null, first.levelCode, ...)`. 784: `bestNode = first.levelCode != null && s0 ? ... : null`.

*suggested_fix*: Require a summary on every split node, or store best = levelBest when s0 is null.

*suggested_fix*: Show MAX(best) as the exit's longest and flag 'level not captured' when it exceeds the best captured level. Alternatively, reject a done node whose best exceeds its parent's captured level when it carries no level.

## Verifier (CONFIRMED, low, refuted=False)
Part A holds. parseTree jobs.js:698 `else if (n.summary != null || n.status === 'done')` makes a split summary optional, and levelBest falls back to level.depth (:708). For children, insNode uses `s ? s.best : n.levelBest` (:790), but for the job's own node finishJob stores `s0 ? s0.best : null` (:782), and bestNode requires s0 (:784). A first node reported split with a level and no summary is therefore stored with level_code set and best NULL. MAX(best) ignores it, and bestOfExit's `ORDER BY best DESC` sorts NULL last. The level sits in the explored part, which no child revisits, so in principle it could lower a published maximum. It is latent: volunteer.py always attaches the SUMMARY to split nodes (the node['summary'] = summary branch before line 620), and the worker prints best/states/valid in every SUMMARY (backsearch.c:5845). Added consequence, checked with an in-memory node:sqlite one-liner: binding undefined throws ('Provided value cannot be bound'). A split summary missing states, valid or best passes sanitizeSummary (needFingerprint only for done), then `s0 ? s0.states : null` / `s ? s.states : null` pass undefined to finishJob or insNode. That throws inside the batch transaction, the whole batch rolls back, v2routes returns 500, and the client treats 500 as transient, so the batch retries forever. Part B also holds in code: a done node with summary.best and no level stores best without level_code, bestOfExit (:299, level_code IS NOT NULL) hides it on status and campaigns, and exitSummary's MAX(best) (:1027-1028) counts it. F115's publish scenario is only partly right, though. With a verified lower champion (149, verified 149) and MAX(best)=150, v2_finish.js:61-64 hits `v != null && v !== best` and refuses before addProof, with the misleading message 'the site solver disagrees'. It publishes the 150 proof only when the champion is unverified (verified_moves NULL) or the exit has no level at all. The worker always prints LEVEL before SUMMARY when best > 0 (backsearch.c:5843), and snapshot rows with best>0 and no level_code: 0, so Part B is latent too. Low.

*fix notes*: In parseTree, require a summary with integer states, valid and best on every split node (sanitizeSummary(needFingerprint: true) for split too). That turns both the best-NULL level and the 500 poison batch into a clean 400. Defensively, finishJob should use `s0 ? s0.best : first.levelBest`, and bestNode should not require s0. In exitSummary/v2_finish, compare MAX(best) with best_level.best and refuse with an explicit 'best without captured level (job N)' message. status/campaignsSummary should show MAX(best) with a 'level not captured' flag. Gate tests: split first node with a level and no summary gives 400 (or best = level depth); split summary without states gives 400, not 500; a done node with best 150 and no level makes v2_finish refuse with the explicit message.
