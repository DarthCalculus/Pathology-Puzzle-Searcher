# M31: jobs.db has no backup at all, and the documented 'Redeploy code from Mac' rsync --delete recipe would delete it and overwrite records.db

verdict CONFIRMED, severity high, category robustness
locations: deployment_pathology.md:35 (rsync --delete over the project root, excluding only records.db-wal/-shm); deployment_pathology.md:50 ('never rsync data/'); /etc/cron.daily/pathology-backup (records.db only, same VPS disk, set up 2026-08-23 before jobs.db existed); local data/ has no jobs.db

## Summary
The only backup, a daily cron, covers records.db, and only onto the same VPS disk. Nothing covers jobs.db, the only record of every campaign's job tree (the evidence behind the published campaign-1 proofs) and of a running campaign's progress. The deploy recipe loaded into every session rsyncs the whole tree with --delete and excludes only records.db-wal and -shm. Because the local data/ has no jobs.db, rsync would delete /opt/pathology/data/jobs.db* and overwrite the live records.db with the Sep 15 local copy, leaving the live WAL in place. Line 50 warns against this, but line 35 is still presented as the recipe.
