# M73: v2_seed --close-others closes the running campaign before validating the new plan, and --dry validates nothing

verdict CONFIRMED, severity low, category robustness
locations: v2_seed.js:68 (closeCampaign commits before createCampaign's checks); --dry only prints the plan

## Summary
closeCampaign commits before createCampaign runs its checks. A plan that fails validation therefore leaves the old campaign closed and no new one open, and every client then hits the 410 loop. The dry run only prints the plan and would not catch the error.

## Source report F104 (server-ingest-routes-tools)
**v2_seed --close-others closes the running campaign before validating the new plan; --dry validates nothing** at /Users/george/PathologyRecords/server/tools/v2_seed.js:68

*summary*: closeCampaign commits before createCampaign runs its checks, and the dry run only prints the plan.

*failure_scenario*: The plan has exits [0,1,2,6,7,13] or a non-hex hash. The dry run passes, then the real run closes #1 and createCampaign throws. No campaign is open until someone fixes it with SQL, and connected clients get 410 (and stay stuck, per the 410 finding).

*evidence*: v2_seed.js:64-69 `if (opt.dry) { console.log('would create campaign:' ...` / `if (open) { jobs.closeCampaign(open.id); ... } campaign = jobs.createCampaign(plan);`

*suggested_fix*: Factor createCampaign's checks into a pure validator, run it (and the layer checks) in --dry and before closing, and do close, create and root insertion in one transaction.

## Verifier (CONFIRMED, low, refuted=False)
v2_seed.js:68-69 is `if (open) { jobs.closeCampaign(open.id); ... } campaign = jobs.createCampaign(plan);`. closeCampaign (jobs.js:379) commits in its own txn. createCampaign (jobs.js:342-371) runs all its validation afterwards and throws: title, grid, canonical exits, hex hashes, integer ranges, CLIENT_PARAM_RANGES. So a bad plan leaves the old campaign closed and none open. The --dry branch (lines 64-66) only prints the plan and fakes `{id:0, exits: plan.exits}`. It never runs createCampaign's checks, so exits [0,1,2,6,7,13], a non-hex hash, lease_cap 500 or split_after_s 0 all pass the dry run. The scenario applies to the next campaign: the snapshot shows campaign 1 is still 'open', so the next seeding needs --close-others. Copying exits [0,1,2,6,7,12] into a plan for another grid is a plausible mistake.
I am correcting the impact claim. SQL is not needed to recover. With no campaign open, re-running v2_seed with the fixed plan (no --close-others needed) creates the campaign. The owner meant to close #1 anyway, and the tool prints the throw right away. The only lasting harm is a gap with no open campaign. During that gap clients get 410 from requireClient (jobs.js:338) or 404 no_campaign from register (jobs.js:451). At startup the client treats 410 as unreachable and retries every 10 s (volunteer.py:342-358). That is the separate 410 finding, which happens on any campaign switch anyway.
An extra consequence the report missed: readLayer (line 73) and addRootJobs (line 78) run after createCampaign. A mistyped --layer-file path, or rejected roots, leaves the new campaign open with zero or only some roots. Clients then lease nothing. There is no false 'complete': auditExit needs roots.length > 0 for clean (jobs.js:1013), and --append can fix it. The dry run does catch a missing layer file, because it calls readLayer. Also, createCampaign accepts `hashes: []`, and --dry does not flag that. Every report would then get 409 unknown_hash and the job is given back until the owner calls addHash, so all volunteer CPU would be wasted. Low severity is right: it is a manual owner tool, the failure is visible at once, and nothing is lost.

*fix notes*: Split createCampaign into validateCampaignPlan(p), a pure function that returns the normalized plan or throws, and the insert. In --dry and in the real run, call the validator, read and parse the layer file, and run addRootJobs-style seed/exit validation (the existing root checks, without the insert) BEFORE closing anything. Then do close + create + root insertion in one db transaction, so a failure leaves the old campaign open and unchanged. Require a non-empty hashes list. Consider warning when a plan hash does not match the SRC_HASH of the worker that produced the layer file. Refuse to create a campaign when the layer yields zero roots for an exit in the plan.
