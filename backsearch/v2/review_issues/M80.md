# M80: The dashboards freeze silently on API failure and show 'No search is running' when the API returns an error body

verdict CONFIRMED, severity low, category robustness
locations: hunt.js:134 (load() returns silently on fetch/JSON failure; error JSON without `campaign` wipes the dashboard); campaigns.js ('No campaign has finished yet.' for any error JSON)

## Summary
load() returns without a trace when fetch or JSON parsing fails, so the old numbers stay up indefinitely. Any JSON error body, such as the outer catch's 400 {error}, lacks `campaign`, and the page wipes the dashboard and says no search is running. campaigns.js likewise shows 'No campaign has finished yet.' for any error JSON.

*suggested_fix*: Check r.ok and `'campaign' in S` before treating the response as 'no campaign'. On failure keep the data but show 'last updated Ns ago, server unreachable' using S.server_time.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed, but the realistic trigger is narrower than the report suggests. hunt.js:134 has `try { S = await (await fetch(...)).json(); } catch { return; }`. While the Node process restarts, Caddy answers 502 with an empty body, so .json() throws and the page silently keeps the old numbers. Nothing marks them as stale, which persists for as long as the server is down. The polls every 3 s recover on their own once it is back. The wipe path is real as well. handleV2 is awaited inside server.js's outer try (server.js:149), and the status route calls jobs.statusCached() synchronously (v2routes.js:97-98). If status() throws, server.js:318-319 answers `sendJSON(res, 400, { error: e.message })`. Then `!S.campaign` holds, and hunt.js:136-139 replaces the intro with 'No collective search is running right now.' and blanks every panel. collective.js:114-118 does the same. status() throwing is rare, though: it only reads (WAL readers do not block, busy_timeout 5000, boards_json parse is wrapped), and the next good poll re-renders everything, so the wipe is transient unless the fault persists. campaigns.js:76-79 does handle fetch or parse failure ('Could not load.'), but any error JSON gives `r.campaigns` undefined and shows 'No campaign has finished yet.'. The same outer catch also returns raw e.message to the public, which is minor. Low severity, UX only.

*fix notes*: Check `r.ok` and `'campaign' in S` before treating a response as 'no campaign'. On failure keep the last render and show a 'last updated N s ago, server unreachable' note, computed from the last good S.server_time plus local elapsed time. In campaigns.js, show 'Could not load' when `!r.ok || !Array.isArray(r.campaigns)`. Consider having server.js's outer catch answer 500 with a generic message rather than 400 with e.message.
