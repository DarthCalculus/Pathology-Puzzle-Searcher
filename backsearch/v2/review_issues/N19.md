## Source report F218 (r2-fix-design-and-acceptance)
**The probe buffer silently drops every child beyond the 64th, which matters for --estimate and for D1 option (a) on large grids** at /Users/george/Documents/Claude Projects/project45/backsearch/backsearch.c:2281

*summary*: In probe mode (--estimate, --list-layer), children beyond 64 are silently dropped. With bulk semantics active, one expansion can emit up to (component size - 1) bulk children plus 12 single steps. That fits 5x5 and 6x6, but not grids with more than about 52 cells (e.g. 8x8), where listed roots would silently miss subtrees.

*failure_scenario*: D1 option (a) is implemented and campaign #3 runs on 8x8. A node's committed component has 60 cells, so it emits 59 bulk children plus up to 12 single children. Seven children never become roots, and their subtrees are missing from the campaign.

*evidence*: backsearch.c:645
  static BState g_probe_buf[64];
backsearch.c:2281-2285
  if (g_probe_n < 64) { g_probe_tagD[g_probe_n] = g_emit_D; ... g_probe_buf[g_probe_n++] = ns; }
  return;

*suggested_fix*: Size g_probe_buf, g_probe_tagD and g_probe_tagV to MAX_NCELLS + 16. When the buffer is full, abort with a clear error instead of dropping. The layer key's '63 - c' ordering needs a wider rank as well (uint8_t key[64] per level is fine up to 255 children).

## Verifier (CONFIRMED, low, refuted=False)
The code is as described. g_probe_buf[64] (backsearch.c:645) and g_probe_tagD/V[64] (186) are fixed at 64, and 2280-2286 drops any child past the 64th with no error.

The claim that this 'matters for --estimate' is false for today's code. g_bulk_walk_active is set only in run_exit_search (4371); it defaults to 0 (196). main calls run_estimate instead of run_exit_search for --estimate and --list-layer (5769), so bulk generation is never active in probe mode. Probe expansions emit only single-step children: at most 4 per direction (d_bufs[4], and the comment says at most 3), so at most 16 per node. The buffer cannot overflow today.

Under the hypothetical D1 option (a), listing with bulk semantics, one node emits at most (component - 1) bulk children plus at most 12 single children:
- 5x5: 23 + 12
- 6x6: 34 + 12
- 7x7: 47 + 12 = 59

All of these fit in 64. Only grids of roughly 7x8 or larger could overflow. The 63-c layer key at 4113 would also need widening there.

This is a real latent silent-drop, but it is unreachable now and irrelevant to a 5x5 or 6x6 next campaign.

*fix notes*: Cheap hardening, worth doing together with D1(a) if that is implemented: size the three probe arrays to MAX_NCELLS + 16 and abort with an error on overflow instead of dropping; widen the per-level sort key rank. No action is needed for the next campaign if D1(a) is not adopted.
