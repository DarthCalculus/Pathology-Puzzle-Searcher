# M83: After a campaign closes, its audit is no longer publicly reachable, although campaigns.html says 'every exit audited'

verdict CONFIRMED, severity low, category docs
locations: v2routes.js:119 (GET /api/v2/audit always audits the active campaign); jobs.audit(exit, campaignId) supports an id; campaigns.html has no audit link

## Summary
GET /api/v2/audit always audits the active campaign. jobs.audit supports a campaign id, but the route never passes one, and campaigns.html has no audit link, so the claim 'every exit audited' cannot be checked publicly once campaign #2 starts.

## Source report F120 (server-web)
**After a campaign closes, its audit is no longer publicly reachable, although campaigns.html says 'every exit audited'** at /Users/george/PathologyRecords/server/lib/v2routes.js:119

*summary*: GET /api/v2/audit always audits the active campaign. jobs.audit(exit, campaignId) supports a campaign id, but the route never passes one, and campaigns.html has no audit link.

*failure_scenario*: campaign #2 is seeded with --close-others, which closes #1. From then on /api/v2/audit reports on #2 (or 404 no_campaign between campaigns). No public page or endpoint shows the covered-roots evidence behind campaign #1's 'exhaustive, every exit audited' claim.

*evidence*: v2routes.js:119 `answer(res, jobs.audit(exit));` ; jobs.js:960-961 `function audit(exit, campaignId, { fresh = false } = {}) { const c = campaignId ? q.campaignById.get(campaignId) : q.activeCampaign.get();`
campaigns.js:52 `(exhaustive, every exit audited)`

*suggested_fix*: Accept `?campaign=ID` on /api/v2/audit (validated integer) and link each exit on campaigns.html to `/api/v2/audit?campaign=${c.id}&exit=${e.exit}`.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed. The route at v2routes.js:110-120 reads only `exit` and calls `answer(res, jobs.audit(exit));`. jobs.audit (jobs.js:960-961) takes a campaignId, but it falls back to q.activeCampaign when none is given. Once campaign #2 is active, or while no campaign is active (404 no_campaign), the detailed audit of campaign #1 can no longer be fetched: covered_roots, the uncovered_roots list, unknown_hash_jobs and mismatches. hunt.js:74 and collective.js:60 also link only to the active-campaign audit, and campaigns.js has no audit link. The finder slightly overstates the gap. campaignsSummary (jobs.js:869) still runs auditExitCached live for every campaign, renders a card only if every exit is clean (line 875), and returns per_exit[].clean and roots in /api/v2/campaigns. So the server's clean verdict for a closed campaign stays public; only the per-root evidence is lost. This is a transparency and documentation gap with no effect on correctness. Low.

*fix notes*: Accept an optional `campaign` query parameter on GET /api/v2/audit (validate it as a positive integer and 404 if unknown), pass it to jobs.audit(exit, campaignId), and link each exit on campaigns.html to /api/v2/audit?campaign=ID&exit=E. Consider caching closed-campaign audits permanently, since their tree no longer changes, to save the per-minute rebuild in campaignsSummary.
