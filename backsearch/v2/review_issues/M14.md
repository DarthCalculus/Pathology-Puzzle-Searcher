# M14: The client dies without cleanup on SIGHUP or SIGKILL: SIGSTOPped (paused) workers stay stopped forever holding RAM, and running windows are lost

verdict CONFIRMED, severity medium, category robustness
locations: volunteer.py:745 (workers started with start_new_session=True); volunteer.py:1352 (handlers for SIGINT/SIGTERM only); pause() sends SIGSTOP; worker has no parent-death check

## Summary
Workers run in their own sessions, Pause sends them SIGSTOP, and the client handles only SIGINT and SIGTERM. When the terminal is closed (SIGHUP) or the client is killed, running workers die of SIGPIPE at their next STATUS write, so the window's work is lost instead of handed back. Stopped workers never write again. Their process group was orphaned by setsid, so the kernel sends them no SIGHUP/SIGCONT, and each stays in state T with at least 160 MiB resident until reboot.

## Source report F35 (worker-io-cli-memory)
**Workers paused with SIGSTOP stay stopped forever if the client dies (e.g. terminal closed); SIGHUP is unhandled** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer.py:745

*summary*: Workers run in their own sessions (start_new_session=True), and Pause sends them SIGSTOP. volunteer.py handles only SIGINT and SIGTERM, so closing the terminal (SIGHUP) or a crash kills the client without cleanup. A running orphan dies of SIGPIPE at its next STATUS write, but a stopped orphan never runs again. Its process group was already orphaned by setsid, so the kernel sends no SIGHUP/SIGCONT, and each keeps at least 160 MiB resident until reboot. The worker has no parent-death check.

*failure_scenario*: A volunteer clicks Pause (16 workers stopped), then closes the terminal window. volunteer.py dies from the default SIGHUP action. 16 stopped workers keep 2.5 to ~9 GiB until a manual kill or reboot. Restarting the client adds 16 more workers on top, and the laptop swaps.

*evidence*: volunteer.py:745 `bufsize=1, start_new_session=True)`; 752 `self._signal(slot, signal.SIGSTOP)`; 1355-1356 install handlers only for `signal.SIGINT` and `signal.SIGTERM`; there is no atexit, pidfile or leftover-worker cleanup. backsearch.c DFS loop 4632-4653 checks only g_stop_requested, never getppid().

*suggested_fix*: Client: handle SIGHUP like Stop; record worker PIDs in a pidfile and, at startup, send SIGCONT+SIGKILL to any leftover workers still running this binary. Worker (defence in depth): exit if getppid() changes, checked at the same 1024-expansion boundary; on Linux, also set prctl(PR_SET_PDEATHSIG).

*expected_gain*: No stranded gigabytes on volunteer machines after an abnormal exit while paused.

## Source report F189 (robustness-ops)
**Closing the terminal (SIGHUP) is not handled: paused workers stay SIGSTOPped forever holding RAM, and running windows are lost** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer.py:1352

*summary*: The client handles only SIGINT and SIGTERM. Workers are started in their own session, so they do not receive the terminal's SIGHUP. ## Verifier (CONFIRMED, medium, refuted=False)
I checked every cited line and the claim holds.

1. Workers get their own session. volunteer.py:743-745 starts them with `subprocess.Popen(argv, stdout=subprocess.PIPE, stderr=stderr, stdin=subprocess.DEVNULL, ..., bufsize=1, start_new_session=True)`. setsid puts each worker in a new session with no controlling terminal, so a terminal hangup never reaches it.

2. Only two signals are handled. volunteer.py:1352-1356 `install_signals` sets `signal.signal(signal.SIGINT, self._on_sigint)` and `signal.signal(signal.SIGTERM, lambda *_: self.request_stop("SIGTERM"))`. There is no SIGHUP handler. main() (1528-1557) calls `sys.exit(vol.run())` with no try/finally, atexit or pidfile.
   - Closing the terminal or dropping an SSH session sends the client SIGHUP, and the default action kills it.
   - An uncaught exception in the main loop also ends it with no cleanup.
   - kill -9 or a force quit can never be handled.

3. Pause uses SIGSTOP in three places:
   - pause() at 1061-1072: `self._signal(s, signal.SIGSTOP)`
   - run_worker at 752 (a worker started while paused)
   - handle_wake at 1264 (up to WAKE_HEARTBEAT_RETRY_S = 120 s after a sleep)

   Only request_stop/_send_stop (SIGCONT+SIGINT) and force_quit (SIGKILL) release stopped workers, and both need a live client.

4. Running workers lose their window. The worker prints STATUS every 250 ms (STATUS_EVERY_MS = 250 at volunteer.py:42; print_status at backsearch.c:4336-4337 does printf + fflush). It installs only SIGINT and SIGTERM handlers (backsearch.c:4866), and Popen's restore_signals resets SIGPIPE to the default. So a running orphan dies of SIGPIPE within about 0.25 s. Its window of up to split_after (1800 s) is lost instead of handed back as REMAINING, and the job waits out its 3600 s lease. This is the same outcome as a second Ctrl-C, not a correctness problem.

5. Stopped workers never resume, and nothing will ever end them. On Linux (kill_orphaned_pgrp) and XNU (fixjobc/orphanpg), the kernel sends SIGHUP+SIGCONT to an orphaned process group with stopped members only when the parent was in the same session but a different process group. setsid breaks that link, so nothing happens when the client dies. The worker's DFS loop (backsearch.c:4632-4653) checks only g_stop_requested, and grep finds no getppid or PDEATHSIG. A stopped process could not run a check anyway. Each orphan stays in state T holding its calloc'd tables until someone kills it, the user logs out, or the machine reboots.
   - SHALLOW_LG2/RECENT_LG2 = 22, so the tables are about 64 MiB + 96 MiB. README says about 200 MB per worker.
   - "At least 160 MiB resident" in the report is too strong. calloc pages count only once touched, and macOS may compress a stopped process's memory. "Up to ~160-250 MiB each" is accurate.
   - With 16 workers that is roughly 2.5-4 GB. A restarted client starts 16 more on top.

6. Realistic trigger. The browser page is the Pause UI. Closing the browser tab is safe: pagehide calls POST /close, then request_stop, which sends SIGCONT+SIGINT. So the stuck state needs the client to die while paused:
   - Pause, then close the terminal. macOS Terminal asks for confirmation first, but the user can accept.
   - Pause, then force-quit the client or log out of SSH (with a forwarded port).
   - A Python crash while paused.
   - A SIGHUP or crash during the 120 s wake re-validation.

   README invites long pauses ("keeps your jobs reserved for up to 12 hours"), which makes a pause-then-close sequence plausible.

Rating: medium, not high. The damage is memory, not CPU; kill or reboot recovers it; no campaign data or result is at risk; the server stops seeing heartbeats, the leases expire after lease_s, and the jobs are re-issued, so nothing stalls; the trigger needs two user actions or a crash. The SIGHUP-while-running half is waste of up to 16 x 30 min per event, which counts as medium waste.

Found in passing (separate doc mismatch): README.md line ~27 says "Closing the page does not stop the search unless you press Stop". The code does the opposite by default: volunteer_ui.html:356-357 sends pagehide to /close, and volunteer.py:1399-1403 then calls request_stop("browser window closed") unless --no-stop-on-close is given. DESIGN §4 says "window close = Stop".

A dynamic run is not needed. The kernel behavior is standard POSIX, and the code paths are unambiguous.

*fix notes*: Order of cost and value:

1. Cheapest structural fix (volunteer.py:745): replace start_new_session=True with a new process group in the same session. Use process_group=0 on Python 3.11+, else preexec_fn=os.setpgrp.
   - Workers still do not get the terminal's Ctrl-C, because the terminal signals only the client's foreground process group.
   - When the client dies for any reason, including SIGKILL, the kernel treats each worker's group as orphaned with a stopped member and sends it SIGHUP+SIGCONT. The worker has no SIGHUP handler, so a paused worker dies, and a running worker dies of SIGPIPE within 250 ms as it does today.
   - Check that the --verbose-workers stderr-to-tty path does not trip SIGTTOU; TOSTOP is off by default.

2. Handle SIGHUP (and SIGQUIT) like SIGTERM in install_signals: `signal.signal(signal.SIGHUP, lambda *_: threading.Thread(target=self.request_stop, args=("SIGHUP (terminal closed)",), daemon=True).start())`. request_stop already sends SIGCONT and then SIGINT, so running windows are handed back as REMAINING instead of lost.
   - Make the module-level log() at volunteer.py:51-56 ignore OSError/EIO from a hung-up tty, keeping the line in the ring. Otherwise the graceful stop crashes on its first log line after the hangup.

3. Wrap vol.run() in main() in try/finally, plus atexit, so every slot with a live proc gets SIGCONT then SIGKILL on any non-graceful exit, such as an uncaught exception.

4. Optional: write worker PIDs to a pidfile in the outbox. At startup, send SIGCONT+SIGKILL to any PID that is still alive and still this worker binary, which covers pre-fix orphans.

5. Worker defense in depth, backsearch.c at the 1024-iteration clock check (4646): record getppid() at startup and exit when it changes. This cannot help a stopped worker, so it only complements 1-3. On Linux, prctl(PR_SET_PDEATHSIG, SIGKILL) also covers the stopped case.

6. Add the regression test from repro_plan to test_client.sh: pause, then kill -9 the client and send SIGHUP to a second client; expect no leftover fake workers. The fake worker must keep Python's default SIGHUP action.

7. Separately, fix README.md: it says closing the page does not stop the search. By default it does, per DESIGN §4 and volunteer.py:1399-1403. Document --no-stop-on-close there.
