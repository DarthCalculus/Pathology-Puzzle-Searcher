# M82: The hunt and collective tables and the live wall overflow phone screens

verdict CONFIRMED, severity low, category bug
locations: hunt.css:23 (live wall grid columns min 300px); per-exit tables (9 and 7 columns, nowrap) without overflow wrapper; body/main/panel padding

## Summary
The live wall's grid columns are at least 300px wide, and the per-exit tables (9 and 7 columns, with nowrap numbers and names) have no overflow wrapper. After body, main.hunt and panel padding, only 256px of content width is left on a 360px phone (286px on 390px), so the page scrolls horizontally.

## Source report F119 (server-web)
**The hunt and collective tables and the live wall overflow phone screens** at /Users/george/PathologyRecords/server/public/hunt.css:23

*summary*: The live wall's grid columns are at least 300px wide, and the per-exit tables (9 and 7 columns, nowrap numbers and names) have no overflow wrapper. Body padding (2x16), main.hunt padding (2x16) and panel padding (2x20) leave 256px of content on a 360px phone and 286px on a 390px phone.

*failure_scenario*: On an iPhone 12-15 (390px) or a 360px Android phone, the .wall column (300px) and the exits table (about 450-500px) are wider than the panel, so the whole page scrolls sideways and the panel backgrounds are cut off. The updates block has a mobile rule; these do not.

*evidence*: hunt.css:23 `.wall { display: grid; grid-template-columns: repeat(auto-fill, minmax(300px, 1fr)); gap: 12px; }`
hunt.css:15-16 `table.chunks { border-collapse: collapse; width: 100%; ... } ... padding: 4px 8px;`
style.css:24 `body { ... padding: 0 16px 60px; }`, hunt.css:3 `main.hunt { ... padding: 0 16px 40px; }`, style.css:33 `.panel { ... padding: 18px 20px; }`

*suggested_fix*: Use `minmax(min(300px, 100%), 1fr)`, wrap the tables in a div with overflow-x:auto (or hide the less important columns under 480px), and drop main.hunt's side padding on narrow screens.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed by reading the CSS and the markup. The viewport meta is width=device-width (hunt.html:5, collective.html:5). style.css:24 sets `body { margin: 0; padding: 0 16px 60px; }`, hunt.css:3 sets `main.hunt { ... padding: 0 16px 40px; }` and style.css:33 sets `.panel { ... padding: 18px 20px; }`. That leaves 360-32-32-40 = 256 px of content width (286 px at 390). hunt.css:23 `.wall { display: grid; grid-template-columns: repeat(auto-fill, minmax(300px, 1fr)); }` forces one 300 px column into 256 px. Nothing in style.css, hunt.css or collective.css sets overflow-x on the panels or on #exitTable, and the only @media rule is the updates rule (collective.css:9). The tables are also too wide. hunt.js:66 has 9 columns and collective.js:75 has 7, each cell with 8 px side padding (hunt.css:16). Their min-content widths come to roughly 450-500 px and about 400 px: the header words are single words, and numbers like '166,733' from toLocaleString cannot break. Both overflow a 256 px panel, so the page scrolls sideways (or Safari zooms out). One small correction: there is no explicit `white-space: nowrap`; the numbers simply have no break points. collective.html is the landing page linked from index.html:24, so phone visitors see this. Cosmetic only.

*fix notes*: hunt.css: `.wall { grid-template-columns: repeat(auto-fill, minmax(min(300px, 100%), 1fr)); }`. Wrap each table in a container with `overflow-x: auto` (e.g. `#exitTable, .people { overflow-x: auto; }`) or hide the less important columns (split, CPU, audit) under 480 px. Add `@media (max-width: 480px) { main.hunt { padding-left: 0; padding-right: 0; } .panel { padding: 14px 12px; } }`. Checking at 360 px width in devtools is enough to test it.
