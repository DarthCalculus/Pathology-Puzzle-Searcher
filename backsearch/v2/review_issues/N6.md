*suggested_fix*: Change §6 and the v2_seed example to layer 4 and note why (until the list-layer / replay mismatch is fixed, K <= 4). Have v2_seed refuse, or warn on, a layer file whose root depths exceed 4, which is cheap because the TSV has a depth column.

## Verifier (CONFIRMED, medium, refuted=False)
Confirmed. DESIGN.md:223-224 says 'layer 8', v2_seed.js:10 has `layer:8`, and the snapshot's campaigns row has layer = 4. §7.1 (234-235) says layer 3 or 4, but §7's header says it overrides only §3/§4, so §6 is formally still in force.

Other places point the same way:
- v2/README.md:55-56: 'the campaign parameters chosen in DESIGN.md §6 are the defaults'.
- backsearch/README.md:235: a recipe using `--list-layer 8`.
- README.md:249: the v1 split recipe `--seed-path P --list-layer 3`.

Nothing guards against it. jobs.js:364/374 stores plan.layer for information only, and v2_seed never compares it with the depth column of the TSV.

The mechanism behind the known defect checks out. --list-layer runs in run_estimate with bulk generation inactive (g_bulk_walk_active is set only at 4371). Replay in build_seed_path_seed (2060-2074) turns a committed-walk run into bulk_walk = 1, and expand then skips those walks. The hazard therefore depends on whether a root's path contains a committed walk, not on K itself. A quick grep found 0 of the 2,761 layer-4 roots containing a push followed by a walk back, which fits the claim that K = 4 was safe.

The docs point the next campaign's setup at a configuration that can silently lose subtrees while the audit stays clean, so medium stands.

*fix notes*: 1. Change §6 and the v2_seed.js example to layer 4, with the reason. Make §7 override §6 explicitly.
2. Fix the v2/README pointer and the backsearch README recipes (layer 8, --list-layer 3 splits).
3. Guard v2_seed on more than depth > 4. Better: have --list-layer flag, or refuse, any root whose path contains a walk onto a committed cell; v2_seed then rejects flagged roots. A depth threshold is only a proxy for other grids and hole counts.
