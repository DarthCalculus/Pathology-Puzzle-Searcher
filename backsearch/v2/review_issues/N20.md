Confirmed. DESIGN.md:224 (§6, 'Parameters for the 5x5 ≤3 holes campaign') says 'layer 8; max_clients 40; ...'. DESIGN.md:4 says 'Change it here first, then the code.' §7.1 (DESIGN.md:234) says 'Campaigns are seeded at layer 3 or 4'. The §7 header (DESIGN.md:227) only claims to override §3/§4, not §6, so the contract really does contradict itself. v2_seed.js:10 has the same example: 'exits:[0,1,2,6,7,12], layer:8'. One more spot the finder missed: backsearch/README.md:235 still shows '--list-layer 8' as the recipe for splitting an exit into jobs. The snapshot's campaigns row has layer=4, and v2/README.md:53-55 points at the depth-4 roots in roots_h3/, so campaign #1 was done right. Two things limit the harm. First, v2_seed.js never uses plan.layer (readLayer at lines 38-48 takes roots straight from the file), so a wrong 'layer' value in plan.json changes nothing by itself. The owner would also have to generate the roots with --list-layer 8. Second, a volunteer cannot trigger this. The D1 mechanism is plausible from the code. run_estimate/--list-layer runs with g_bulk_walk_active=0, because it is only set inside run_exit_search at backsearch.c:4371 and main does 'run_estimate(); continue;' at 5769. The listed tree is therefore built without bulk walk-back. Jobs replay those paths with bulk on, and build_seed_path_seed (2060-2074) turns a trailing committed-walk run into a bulk_walk=1 node that skips its own committed walk-backs. So the lead's measured loss at deep layers fits the code. This remains a documentation defect, and the real danger sits in D1 itself: nothing in code rejects a deep layer. So I rate it low, with a critical-class consequence if someone copies the text for campaign #2 (for example on a new grid, where K has to be chosen again).

*fix notes*: Change DESIGN.md §6 and the v2_seed.js:10 example to layer 4, and fix or annotate backsearch/README.md:235. Write the D1 rule into §6/§7.1 as a hard rule. Also enforce it in code: v2_seed should refuse roots whose token count exceeds the safe K (or check each root against plan.layer and refuse deeper ones), and/or the worker's --list-layer should refuse K > 4 unless --no-bulk-walk is given.
