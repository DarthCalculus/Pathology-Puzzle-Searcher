# M59: With 'Any exit' selected, 'best known globally' shows the lowest-numbered exit's best, not the global best

verdict CONFIRMED, severity low, category bug
locations: volunteer_ui.html:312 (picks the first exit in numeric order that has a best)

## Summary
With no exit preference, the global board shows the first exit in numeric order that has any best, instead of the exit with the most moves. For campaign #1 it would show exit 0's 127 instead of exit 1's 149.

## Source report F65 (client-ui)
**With 'Any exit' selected, 'best known globally' shows the lowest-numbered exit's best, not the global best** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer_ui.html:312

*summary*: When there is no preference, the global board picks the first exit in numeric order that has any best, instead of the exit with the most moves.

*failure_scenario*: With campaign #1 values and exit preference Any, the board reads 'best known globally, exit 0 · depth 127', although the global record is 149 at exit 1. A volunteer reads 127 as the best known.

*evidence*: volunteer_ui.html:312 `const selExit = st.exit_pref != null ? String(st.exit_pref) : (st.exits ? Object.keys(st.exits).sort((a, b) => a - b).find(e => st.exits[e].best) : null);`

*suggested_fix*: When exit_pref is null, choose the exit whose best.moves is largest.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed. Line 312: `const selExit = st.exit_pref != null ? String(st.exit_pref) : (st.exits ? Object.keys(st.exits).sort((a, b) => a - b).find(e => st.exits[e].best) : null);` With 'Any exit' (exit_pref null) this takes the lowest-numbered exit that has any best, not the exit whose best.moves is largest. With campaign #1 values (exit 0 = 127, exit 1 = 149) the board is captioned 'best known globally, exit 0 · depth 127'. DESIGN.md §8 item 3 specifies 'best known globally for the selected exit', which leaves the no-selection case undefined, but 'globally' plus 'Any exit' naturally reads as the overall best. Two things soften the impact: the caption does name the exit, and the Campaign table in section 5 lists every exit's best (149 at exit 1) on the same page. It remains a wrong or misleading display, which is low severity.

*fix notes*: When exit_pref is null, pick the exit with the largest best.moves, e.g. `Object.keys(st.exits).filter(e => st.exits[e].best).sort((a,b) => st.exits[b].best.moves - st.exits[a].best.moves || a - b)[0]`. Optionally caption it 'best known overall (exit N)' so it is clearly different from the per-exit view.
