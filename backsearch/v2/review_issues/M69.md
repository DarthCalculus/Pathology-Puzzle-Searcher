# M69: The audit counts an exit clean while dup jobs are still outstanding, so a proof can be published before the fingerprint sample finishes

verdict CONFIRMED, severity low, category protocol
locations: jobs.js:1013 (auditExit considers only dups that already mismatch); v2_finish (publishes once the tree is covered)

## Summary
auditExit looks only at dups that already mismatch. Open or leased dup jobs do not stop 'clean', and v2_finish publishes as soon as the tree is covered, so a mismatch that lands after publication is never considered.

## Source report F86 (server-scheduling)
**The audit counts an exit clean while dup jobs are still outstanding, so a proof can be published before the fingerprint sample finishes** at /Users/george/PathologyRecords/server/lib/jobs.js:1013

*summary*: auditExit looks only at dups that already mismatch. Open or leased dup jobs do not stop 'clean', and v2_finish publishes as soon as the tree is covered.

*failure_scenario*: Campaign #1's tree was complete at 09:17:09, but its last 7 dups (created 02:11-02:57) finished only between 12:58 and 13:00. Running v2_finish --publish at 09:20 would have published before those checks. A later mismatch would turn the audit unclean with the proof already in records.db, and nothing flags or retracts it.

*evidence*: 1005: `for (const d of q.dupsOfExit.all(c.id, exit)) if (d.mismatch) mismatches.push(...)`. 298: dupsOfExit filters `mismatch = 1 OR status IN ('done','split')`, and open/leased dups are ignored. 1013: `clean: roots.length > 0 && uncovered.length === 0 && unknown.length === 0 && mismatches.length === 0`. Snapshot: max non-dup done_at 09:17:09; 7 dups done 12:58:10-13:00:26.

*suggested_fix*: Report pending_dups in the audit and have v2_finish refuse, or warn, while any dup of that exit is open or leased.

## Verifier (CONFIRMED, low, refuted=False)
Code matches the claim. jobs.js:298 dupsOfExit selects only `dup_of IS NOT NULL AND (mismatch = 1 OR status IN ('done','split'))`, and jobs.js:1005 pushes only rows with d.mismatch, so open or leased dups never affect `clean` (jobs.js:1013). v2_finish.js:38-47 publishes as soon as a.clean is true. Its 'pending' count, `a.counts.open + a.counts.leased`, comes from treeOfExit rows (dup_of IS NULL), so the owner never sees pending dups either. Snapshot check: the last non-dup done_at is 09:17:09. Seven dups created 02:11-02:57 stayed open until a client leased them at 12:58:09-13:00:26. No reports at all arrived between 09:20:04 and 12:58, so a publish in that gap would have skipped them. All 1,033 dups in the snapshot match (sum(mismatch)=0), so campaign #1 was not affected. Added consequences: (1) If a mismatch lands after publishing, campaignsSummary (jobs.js:872-874) quietly drops the whole campaign from campaigns.html, because per.every(clean) fails, while the proof stays in records.db. The public state is then inconsistent and nothing explains it. (2) Once the campaign is closed, requireClient returns 410, so pending dups can never run and the sample stays incomplete for good. (3) Late duplicate reports on already-done jobs can also set mismatch after publication (applyReport, finished branch), so waiting for dups narrows the window but does not close it. (4) In the snapshot, dup 19677 (orig 19225) and dup 20762 (orig 20609) were run by the same client token as their originals. The lease path excludes that (openOfExit :274), but work stealing (leasedOthers :266) does not, so some fingerprint checks are not cross-machine. Low severity: the dup sample is a 2% statistical sanity check and publishing is a manual owner step.

*fix notes*: In auditExit, count dups of the exit with status IN ('open','leased') and return pending_dups. Have v2_finish refuse, or require an explicit --ignore-pending-dups, while pending_dups > 0, and print the count in its head line. Record a published marker per exit and log or flag loudly (e.g. a banner on campaigns.html) when a mismatch appears after publication, instead of silently hiding the campaign. Exclude dups whose original was run by the stealing client from the leasedOthers candidates. Gate test: create a dup with reissueJob, leave it open, assert audit.pending_dups=1 and that v2_finish refuses.
