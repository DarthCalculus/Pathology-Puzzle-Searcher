# M49: An unreplayable seed ends with exit code 0 and SUMMARY status 'time_cap', and the job churns between clients forever

verdict CONFIRMED, severity low, category protocol
locations: backsearch.c:4386 (build_seed_path_seed rejection -> exhausted=0, split_fired=0; main prints a normal report and returns 0); volunteer.py (ignores statuses other than exhausted/split)

## Summary
When build_seed_path_seed rejects a step, the worker prints a normal SUMMARY with status time_cap and states 0, and returns 0 rather than an error. The client ignores that status, logs 'exited with code 0 WITHOUT a SUMMARY line', and leaves the job untouched. The lease is released by omission, and every next client fails the same way, with no error surfaced anywhere.

Each client that leases one fails instantly, and the job circulates indefinitely. It shows up only as an uncovered root in the audit, with a misleading log line.

*suggested_fix*: Print SUMMARY status `bad_seed` and exit with a distinct code (e.g. 3). The client should report it, and the server should mark the job `error` so the owner sees it instead of an endless retry.

*expected_gain*: Replay failures become visible and do not silently stall an exit.
