*suggested_fix*: When a level falls in a proven class (levelInClass) and its claimed or proposed length exceeds the proof's maxMoves, either refuse it at submitLevel/claimLevel or tag it 'contradicts proof #N' and keep it out of the record slot.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed. annotateChampions skips every non-verified level at db.js:588: 'if (!lv || lv.status !== 'verified') continue;'. So a 'claimed' level never gets lv.contradicts, and app.js:120 draws the 'contradicts proof' badge only from lv.contradicts. None of the write paths look at proofs. The claimProven branch of processSubmission (pipeline.js:81-95) accepts a bare number as moves with status 'claimed' when the site solver returns too_complex. claimLevel (db.js:380-398) promotes unproven to claimed. submitLevel does only dominance checks. addProof (db.js:654-667) uses proofChampions, which searches statuses ['verified'] only, so a stored claimed level above the maximum does not block the proof either. The default tiers are verified+claimed (server.js:118-121), searchLevels orders by moves DESC, and levels[0] becomes 'record'. The search response has a 'proof' field, but app.js never renders it, so nothing else on the page flags the conflict. A claimed length above a covering proof's maxMoves is a provably false optimality assertion, yet it would be shown as the record above the champion badged 'none is longer'. What limits this: the scenario needs a level the site solvers cannot finish (too_complex). For a 5x5 that is unlikely, since the campaign #1 champions were re-solved by the site. It becomes realistic for a larger grid in campaign #2 (5x6/6x6), and for existing external 'claimed' entries in a class a later campaign proves. The local snapshots have 0 claimed levels today. Public display integrity only, no campaign data at risk, so low.

*fix notes*: In annotateChampions, also evaluate 'claimed' (and optionally 'proposed') levels against covering proofs. Tag a claimed level with moves > p.maxMoves as contradicts, and keep it out of the record slot, or sort it below the proven champion. At submission (pipeline claimProven path and claimLevel), refuse a claimed length above a covering proof's maxMoves (levelInClass). Have addProof report stored claimed levels above maxMoves so the owner sees them when publishing campaign #2.
