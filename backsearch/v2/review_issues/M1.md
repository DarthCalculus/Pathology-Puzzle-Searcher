# M1: --list-layer lists roots with bulk walk-back off, but jobs replay them with it on: a root ending in a committed-walk run loses its parent's deeper bulk siblings

verdict CONFIRMED, severity critical, category soundness
locations: backsearch.c:2074 (build_seed_path_seed folds a trailing committed-walk run into a bulk edge, bulk_walk=1); backsearch.c:2060; backsearch.c:4371 (g_bulk_walk_active is set only in run_exit_search); backsearch.c:2476/2526 (expand() skips committed walk-backs when bulk_walk=1); run_estimate / --list-layer path

## Summary
g_bulk_walk_active is set only in run_exit_search. run_estimate (--list-layer) therefore expands committed walks as single-step children, so a layer root can end in a walk onto a committed cell. A job that replays such a root with bulk on folds the trailing run into one bulk edge (bulk_walk=1). expand() then skips every committed walk-back. In the bulk tree those farther cells are bulk children of the run's start node, which sits above the layer and belongs to no job, so their subtrees and any valid levels in them are never searched. Campaign #1 (layer 4) is unaffected: 0 of 2,761 roots contain a committed walk. Any campaign seeded at K>=5, such as DESIGN §6's 'layer 8', is exposed, and the split and chaos tests use layer-2 roots, so they cannot catch it.

1. Listing side: bulk walk-back is off.
- backsearch.c:196 declares `static int g_bulk_walk_active = 0;`. Its only assignment is at 4371, inside run_exit_search: `g_bulk_walk_active = g_bulk_walk && g_beam_width == 0 && ...`.

- In run_estimate (4100-4122), expand() at 2476 does not skip committed walks (`if (g_bulk_walk_active && ...) skip_committed_walks = ...`). Each walk onto a committed cell becomes a single-step child (2524-2536, bulk_walk=0) and goes into g_probe_buf.
- Layer roots are cut at depth exactly K (4129-4136). So a root can end in a run of single-step committed walks.

2. Job side: bulk is on, and the trailing run becomes a bulk edge.
- In build_seed_path_seed, 2060-2061: `committed_walk = V == 1 && C >= 0 && (seed.committed_empty >> C & 1) && g_bulk_walk_active && (run || ...)`.
- 2074: `if (run) { seed.wh = 0; seed.bulk_walk = 1; ... }`.
- run_exit_search passes the seed to try_successor (4401) and then expand(). At 2476, `skip_committed_walks = s->bulk_walk ? 1 : bulk_generate(s)` evaluates to 1, and 2526 (`if (skip_committed_walks && (s->committed_empty >> C & 1)) walk_ok = 0;`) drops every committed walk-back.

3. What is lost.
- Let S be the non-bulk start of the run, at depth d < K. In the monolithic bulk tree, every cell of S's committed component at walk distance > K-d is a direct bulk child of S (bulk_generate 2356-2379).
- In the listing tree those cells exist only as children of the trailing roots. The trailing-root jobs skip them, and S is never expanded by a job. They and their subtrees are therefore covered by no job.
- No other root regenerates them. Their state has S's blocks, masks and committed set, and every descendant of another root has a strictly grown committed set or different blocks.
- Cutting after a non-committed step is consistent: the replay folds the run into the same bulk child the DFS makes. So only a trailing run loses anything.
- REMAINING seeds are not affected. In a bulk-on DFS every committed-walk token belongs to a bulk edge: bulk_generate always returns 1, and even its rc<0 fallback emits bulk_walk=1 children. So a replayed REMAINING path reproduces its true flag.

- In run_estimate, set g_bulk_walk_active with the same expression used at 4371.
