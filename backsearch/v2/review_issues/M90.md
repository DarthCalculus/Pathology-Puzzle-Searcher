## Verifier (CONFIRMED, medium, refuted=False)
The claim holds after reading the code. In test_chaos.sh:53-56 (`for i in $(seq 1 120); do [ "$(audit_clean)" = 1 ] && break; sleep 2; done`) the loop just ends after 240 s. Line 60 (`echo "audit clean: $(audit_clean)"`) only prints the value. The script's exit status is set by three things: line 58 (split > 0, else exit 3), line 59 (server best == FULL_BEST, else exit 4) and the python block at 63-85 (RC=$?). DESIGN.md:201 lists 'audit clean' as an assertion, so the script does not do what the contract says.

In jobs.js:1010 `clean` is `roots.length > 0 && uncovered.length === 0 && unknown.length === 0 && mismatches.length === 0`. A clean audit would therefore also cover the dup fingerprint check (DESIGN §5.4 'no mismatch'). That check is never asserted either: a nondeterministic worker that makes one of the dup_fraction 0.05 re-issues mismatch still passes.

The stall case is real. If a job is run but its report is repeatedly refused, or a lease is never released, the job never becomes done. Its levels still sit in the workers' traces, so the union check passes and the script exits 0.

Two extra points:
- The HTTP audit endpoint is served from a 60 s cache (jobs.js:49 AUDIT_TTL_S=60, auditExitCached). v2routes.js:119 calls jobs.audit(exit) with no fresh option, so the 2 s poll really sees a new value only once a minute. Line 60's echo can show a stale value.
- The test is red for a different reason right now. The lead observed it stops at line 58 with 'no job was split', so this gap bites as soon as the split regime is restored.

Rated medium. It is the only end-to-end pre-campaign gate for stealing, release and re-issue, and without the assertion those bugs would first show up mid-campaign as a stuck audit. It cannot directly make a published result wrong: a false 'clean' would still be caught by the union.

*fix notes*: After the loop add `[ "$(audit_clean)" = 1 ] || { echo 'FAIL: audit not clean after 240 s'; curl -s "$URL/api/v2/audit?exit=7"; exit 5; }`. Because of the 60 s cache, either poll for at least 60 s after the last report or run the server-side check with a fresh audit (tools/v2_finish.js-style jobs.audit(exit, id, {fresh:true})). Also assert that the audit's mismatches are empty (included in clean) and that at least one dup comparison happened, e.g. from status totals.dups > 0 or the reports table 'dup' rows in $T/data/jobs.db. Fix the doc and header mismatch at the same time: both say leases expire in 5 s, but plan.json sets lease_s 30.
