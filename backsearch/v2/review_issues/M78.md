# M78: The collective page never shows when a champion was found: it reads best_level.done_at, but status sends best_level.at

verdict CONFIRMED, severity low, category bug
locations: collective.js:98 (renderBest checks b.done_at); jobs.js status() builds best_level with key `at`

## Summary
renderBest adds the age only when b.done_at is truthy. status() builds best_level with the key `at`, so the condition is always false and 'found ... ago' never appears.

## Source report F111 (server-web)
**The collective page never shows when a champion was found: it reads best_level.done_at, but status sends best_level.at** at /Users/george/PathologyRecords/server/public/collective.js:98

*summary*: renderBest adds the age only when b.done_at is truthy. status() builds best_level with the key `at`, so the condition is always false.

*failure_scenario*: Any campaign with a best level: the caption reads 'exit 1: 149 moves, found by X' and never adds ', 3.2 h ago', although the code intends to.

*evidence*: collective.js:98 `${b.done_at ? ', ' + ago(Math.max(0, Math.round(Date.now() / 1000 - b.done_at))) : ''}`
jobs.js:907 `e.best_level = { job_id: b.id, code: b.level_code, moves: b.best, verified_moves: b.verified_moves, by: b.name, at: b.done_at };`

*suggested_fix*: Use b.at, and compute the age from S.server_time rather than the viewer's clock.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed. collective.js:98 renderBest shows the age only when `b.done_at` is truthy: `${b.done_at ? ', ' + ago(Math.max(0, Math.round(Date.now() / 1000 - b.done_at))) : ''}`. The object it reads comes from /api/v2/status. v2routes.js:97-98 sends jobs.statusCached(), which caches status(), and jobs.js:907 builds `e.best_level = { job_id, code, moves, verified_moves, by: b.name, at: b.done_at }`. The key is `at`, never `done_at`, so the branch is always false and 'found ... ago' never appears. The heartbeat payload (jobs.js:558) also uses `at`. hunt.js renderBest (80-94) does not try to show the time, so only collective.js is affected. Display only: no data or correctness effect, so it stays low.

*fix notes*: In collective.js:98 read `b.at`, and compute the age as `S.server_time - b.at`, not from the viewer's Date.now(), to avoid clock skew (server_time can be up to 2 s old because of the status cache, which is fine). A one-line check in v2_gates.test.js that status().perExit[i].best_level has `at` would stop the names drifting apart again.
