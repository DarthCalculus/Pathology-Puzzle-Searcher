# M53: --exit is not validated: an exit outside the campaign makes every lease fail with 400, forever

verdict CONFIRMED, severity low, category robustness
locations: volunteer.py:470 (command-line exit preference sent unchecked); set_exit() validates only UI values; server 400 'exit is not part of the campaign'

## Summary
The command-line exit preference is sent without a check. The server answers 400 'exit is not part of the campaign', and the leaser only logs and retries every 10 s with the same preference, so the client never gets work (for example, when a campaign #1 exit is passed in campaign #2).

## Source report F56 (client-core)
**--exit is not validated: an exit outside the campaign makes every lease fail with 400, forever** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer.py:470

*summary*: The command-line exit preference is sent unchecked. The server returns 400 'exit is not part of the campaign', and the leaser only logs and retries every 10 s with the same preference, so the client never receives work. set_exit() validates only values set from the UI.

*failure_scenario*: A volunteer runs with `--exit 3` (not a canonical cell), or keeps `--exit 7` in a launcher when campaign #2 has other exits. Every lease returns 400, all workers idle indefinitely, and the panel shows 'new leases use exit 3' forever.

*evidence*: volunteer.py 225: self.exit_pref = args.exit
volunteer.py 467-470: if pref is not None: body["exit"] = pref
volunteer.py 473-478: except ApiError as e: (only 403 revoked stops) self.log("lease failed ..."); continue
jobs.js 571-572: if (!isInt(body.exit, 0, MAX_AREA - 1) || !exitsOf(c).includes(body.exit)) return fail(400, 'exit is not part of the campaign');

*suggested_fix*: After register, validate args.exit against campaign['exits'] and fall back to 'any' with a warning. On a 400 lease that carried an exit preference, clear the preference and retry.

*expected_gain*: A typo can no longer silently zero a volunteer's contribution.

## Verifier (CONFIRMED, low, refuted=False)
The issue holds. volunteer.py:225 sets `self.exit_pref = args.exit` with no check. args.exit is only `type=int` (:1532), so negative values and 25+ also pass. set_exit (:1040-1059) checks against campaign['exits'], but only the UI POST path at :1498 calls it; startup never does. The leaser (:467-470) adds `body["exit"] = pref` to every request. The server rejects it before the transaction: jobs.js:571-572 `if (!isInt(body.exit, 0, MAX_AREA - 1) || !exitsOf(c).includes(body.exit)) return fail(400, 'exit is not part of the campaign')`. The fallback-to-any-exit logic (jobs.js:590-600) is never reached in this case. In the client's ApiError handler (:473-478), only 403 'revoked' stops the loop. Everything else logs 'lease failed (HTTP 400: ...)' and continues, so the same bad preference is resent every batch_interval_s (10 s) forever. Nothing is leased and every worker stays idle. The panel shows 'current jobs finish first; new leases use exit N' (:1241-1242) indefinitely. A GUI user can recover by picking another exit in the panel, since set_exit validates. A --no-ui user must notice the log spam and restart. One side effect: heartbeats keep updating last_seen (jobs.js:830/848), so the stuck client's declared workers still count in sumWorkers/workersActive (jobs.js:277, 581). That makes the server's ramp test `open < 3 * workersActive` pick the short ramp split_after for everyone slightly more often. No correctness impact and nothing is lost; only this volunteer's contribution is zeroed. Realistic triggers are a launcher that still has `--exit 7` from campaign #1 when campaign #2 has different canonical exits, or a volunteer passing a non-canonical cell such as 3 or 4. Low severity stands.

*fix notes*: After register() and apply_campaign() (before run()), pass args.exit through the same validation as set_exit. If it is not in campaign['exits'], log a clear warning, listing the valid exits, and fall back to None (any). In the leaser, on ApiError 400 with error 'exit is not part of the campaign' while pref is not None, clear exit_pref under the lock, log it, and retry at once. This also covers a campaign whose exits change between heartbeats. Add a test_client.sh case: the fake server lists exits [0,1] and the client starts with --exit 7. Assert that it leases jobs within one batch interval.
