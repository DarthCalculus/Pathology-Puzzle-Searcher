*suggested_fix*: WORKER
- Set g_seed_error=1 in the 4386 branch.
- st = "bad_seed", with an 'error' string such as 'step i (D1) invalid at depth d'.
- main returns 3. Each new status gets its own exit code.

CLIENT (run_worker 804-818)
- Keep the parsed SUMMARY whatever its status.
- Return a failure {reason: status or 'no_summary', rc, stderr tail}. Capture a bounded stderr tail even without --verbose-workers.
- In run_window: a failure of J queues a failure report {job_id, src_hash, failure:{reason, rc, detail<=300}}, removes J from 'holding', and is not retried in this window. A failed child stays open.

SERVER (jobs.js)
- Add columns fail_count, fail_tokens_json, last_fail (ALTER TABLE in openJobsDB).
- Accept a failure element in /api/v2/reports, from whitelisted hashes only.
- On a failure: increment fail_count and reopen the job. At 3 or more failures from 2 or more distinct tokens, set status 'poison'. Poison is not leasable, and the existing status='open' lease queries already exclude it.
- auditExit: poison nodes count as uncovered, listed as poison_jobs with reasons; clean=false.
- Status totals include poison.
- New tool v2_jobs.js inspect|unpoison <id>.

FAKES AND TESTS
- fake_worker: FAKE_STATUS=bad_seed.
- fake_server: mirror.
- Gate tests for counting, poison, the audit and non-leasing.

DESIGN §2/§3: statuses and exit codes.

CONFLICTS
- The known 'same job twice in one batch' bug must be fixed before a failure and a tree report for the same job can share a batch.
- Failures must not count as first-report-wins coverage.
- Stealing and release-by-omission re-grant jobs freely, so count failure reports, not leases.

## Verifier (CONFIRMED, medium, refuted=False)
The mechanism holds at every link I checked. I cannot say bad seeds are likely to occur, and the audit stops the stall from becoming a false "complete".

WORKER (backsearch.c)
- 4386-4389: when build_seed_path_seed fails, run_exit_search sets *out_exhausted=0 and *out_dedup_full=0 and returns 0.0. g_split_fired was already set to 0 at 4378.
- main (5844) then prints `SUMMARY {"status":"time_cap",...,"states":0}`, prints the "Backward search complete" block and returns 0 (5928). The rc is 0.
- The only diagnostic is the stderr line from build_seed_path_seed (2068 `error: --seed-path step %d (%c%d) is invalid at depth %d`).
- Seed text that fails to parse, or is longer than 1024 tokens, is caught earlier at 5116-5122 with rc 1 and no SUMMARY. The client handles that the same way.

CLIENT (volunteer.py)
- run_worker opens stderr as DEVNULL unless --verbose-workers is set (731), so the diagnostic is thrown away.
- 804: `if isinstance(s, dict) and s.get("status") in ("exhausted", "split"): summary = s`. A time_cap SUMMARY is therefore discarded.
- The client then logs a misleading "exited with code 0 WITHOUT a SUMMARY line" and returns None. It never looks at rc.
- run_window 596-601: if J is the seed, it sets slot.job=None and returns False ("J itself produced nothing: job untouched"). No report is queued. slot_loop only bumps the per-slot consecutive_failures back-off (548-556).

SERVER (jobs.js)
- The next heartbeat's `holding` no longer includes J. At 514, `if (holdingSet && !holdingSet.has(j.id) && t - j.leased_at > RELEASE_GRACE_S) q.reopenJob.run(j.id)` reopens J after 120 s. reopenJob (284) only resets the status and lease fields.
- The jobs schema (184-208) has no attempt or failure column, and nothing in jobs.js or v2routes.js counts failures. openOfExit (273-275) hands J out again as usual.
- A child that fails inside a window is marked node.status='open' (602). It becomes an open job and goes through the same loop.
- The result is an endless lease, 0 s run, release every ~120 s with no counter and no reason recorded. DESIGN.md and README.md do not define failure handling anywhere.

WHY IT DOES NOT CORRUPT RESULTS
- auditExit (1006-1013) leaves J uncovered, so clean=false.
- v2_finish.js:41-43 refuses to finish an exit that is not clean.
- So this is a stall that shows in the audit as an uncovered root (id, seed, status) with no reason attached. It cannot make a published result wrong.

REACHABILITY
- Campaign #1 finished all 166,733 jobs, and test_split_exact lost nothing. Seeds generated by the worker's own REMAINING lines evidently replay fine under a consistent hash and consistent flags.
- Realistic triggers for the next campaign:
  - The layer listing is regenerated with flags more permissive than the campaign's. The next campaign changes holes or grid, and apply_seed_step 1931-2031 rejects on g_max_holes, g_max_blocks, g_walkable_mask and exit-transit. v2_seed.js only syntax-checks seeds with parseSeed and never replays them.
  - A worker hash is swapped mid-campaign with changed move semantics, leaving open REMAINING seeds from the old hash.
  - A seed that makes the worker crash every time (rc != 0, no SUMMARY). None is known; ASan was clean on 12 roots. It would re-burn up to one split window of CPU on every attempt, forever.

SEVERITY
The consequence when triggered fits "stall" (high), but there is no known in-code source of bad seeds. The symptom is visible in the audit, no result can be falsified, and the stall ends once the owner diagnoses it by hand. I rate it medium for the next campaign. It is still worth fixing before launch, because recovery today needs manual DB surgery and the diagnostic is discarded.

*fix notes*: The proposed D7 design is sound. Corrections and additions:

1. WORKER: g_seed_error does not exist yet, so add it. Set it in the 4386 branch and also in the rollout (3599) and list-layer (4082) callers. Emit status "bad_seed" plus an "error" field, and have main return 3. Also have the client treat any SUMMARY status that is not exhausted/split as a failure. That covers time_cap, which cannot legitimately happen with --time 0, and it also works with old binaries.

2. CLIENT run_worker 731: always capture stderr through a pipe. Read it in a thread or drain it after stdout closes, and keep a bounded tail (for example the last 2 KB). Stop logging "WITHOUT a SUMMARY" when a SUMMARY was present. Return a failure object {reason, rc, detail}. Do not count a failure when slot.killed_by_client is set or when the stop was requested by the client (SIGINT on stop), otherwise stopping the client creates false failures. The test_client e flake (SIGINT before the handler is installed, exit -2) is exactly this case. Also consider scrubbing BS_* debug variables from the worker's environment. Popen inherits os.environ, and BS_DUMP_SEED (backsearch.c 4394) makes every run report status "exhausted" with 0 states. A volunteer with that variable set would falsely cover every subtree they touch. It is low probability, but it is cheap to close.

3. SERVER
- Count failures per report, not per lease.
- Poison a job only at 3 or more failures from 2 or more distinct tokens, so one broken client cannot poison jobs by itself. Also back off or flag a token whose failure rate is high.
- Poison must be excluded by openOfExit, which already filters status='open'. The heartbeat reclaim at 532 checks j.status==='open', so a poisoned job correctly goes to `drop`. stealJob requires 'leased'.
- auditExit must list poison nodes with their reasons. Check that the status counts and the public pages (collective/campaigns JS) tolerate the new status key.
- Provide v2_jobs.js inspect|unpoison.

4. SEEDING (not in the original proposal, and a better guard against the most likely trigger): v2_seed.js should replay-validate every root with the campaign's exact argv. Use `--print-seed-key` together with the grid, --exit, --seed-path and the plan's extra flags, and reject roots that fail with rc 1. Ideally the layer TSV header should also record the listing flags and SRC_HASH, and v2_seed should refuse on a mismatch. A listing made with LESS permissive flags than the campaign (for example fewer holes) replays cleanly but silently leaves subtrees out of the root set. Failure accounting cannot catch that, and it would be a coverage (critical-class) error.

5. TESTS: add FAKE_STATUS=bad_seed and FAKE_RC to fake_worker. Add gate tests for failure counting, poisoning at 2 distinct tokens, non-leasing, the audit listing, and "client stop does not count as failure".
