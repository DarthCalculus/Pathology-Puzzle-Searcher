# M62: The actionable stop reason is replaced by a generic banner 2 s after the client exits

verdict CONFIRMED, severity low, category robustness
locations: volunteer_ui.html:353 (after 8 failed polls the banner text is overwritten with 'The client is not answering')

## Summary
While stopping, the banner shows stop_reason, for example the instruction to update and rebuild. Once the process exits, 8 failed polls later the same element is overwritten with 'The client is not answering', and the actionable reason disappears from the panel.

## Source report F68 (client-ui)
**The actionable stop reason is replaced by a generic banner 2 s after the client exits** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer_ui.html:353

*summary*: While stopping, the banner shows stop_reason, for example the instruction to update and rebuild. Once the process exits, 8 failed polls later the same element's text is overwritten with 'The client is not answering', and the reason is lost from the panel.

*failure_scenario*: The owner removes a worker hash. The heartbeat triggers request_stop('the campaign's accepted worker hashes changed; update and rebuild (git pull && ./build_pgo.sh)'). The client finishes and exits. A volunteer who looks at the tab later sees only 'The client is not answering (stopped or exited). You can close this tab.' and does not learn they must rebuild.

*evidence*: volunteer_ui.html:265 `if (st.stopping) { ... banner.textContent = 'Stopping: ' + st.stop_reason + '.'; }`, then :353 `b.textContent = 'The client is not answering (stopped or exited). You can close this tab.';`

*suggested_fix*: Remember the last stop_reason in JS and show it in the not-answering banner, for example 'The client stopped: <reason>'.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed. While stopping, render() at line 265 sets `banner.textContent = 'Stopping: ' + st.stop_reason + '.'`. After the client's run() loop finishes and the process exits (volunteer.py:1406-1426, then sys.exit), the UI port closes and fetches reject. Eight failures later (about 2 s), line 353 overwrites the same #banner element with 'The client is not answering (stopped or exited). You can close this tab.' Nothing in JS keeps the reason. Stop reasons that need action exist: volunteer.py:1183 'the campaign's accepted worker hashes changed; update and rebuild (git pull && ./build_pgo.sh)', and :920/:942 for rejected hashes. Three things mitigate it: (1) request_stop logs the reason to stderr (log() at volunteer.py:51-56), so the terminal shows it unless the launcher window closed. (2) The page's #log <pre> is not cleared on failure, so the last rendered log still holds 'stopping: <reason>', but only inside the collapsed 'Client log' <details>. (3) At the next launch, check_hash tells the volunteer again that the hash is not accepted. So the reason disappears from the prominent banner but is not lost entirely. Low severity.

*fix notes*: Store lastStopReason whenever st.stopping is true, and use it in the not-answering banner: 'The client stopped: <reason>. You can close this tab.' Keep the 'bad' class for stops caused by the server (hash, revoked) so the rebuild instruction stays visible.
