# M22: The final heartbeat on Stop carries no `holding`, so the abandoned lease-ahead queue is renewed for lease_s instead of released

verdict CONFIRMED, severity low, category robustness
locations: volunteer.py:1417 (final heartbeat); request_stop clears the local queue; jobs.js heartbeat renew/release logic

## Summary
This extends the known 'unstarted leases are not released' issue. request_stop clears the local queue, and the last heartbeat is sent without `holding`, so the server renews every lease on the token, the abandoned ones included, to now + lease_s (3600 s). Since §9, sending holding=[] would release them at once through the existing 120 s release-by-omission rule, with no new route.

## Source report F53 (client-core)
**The final heartbeat on Stop omits `holding`, stranding all leased-ahead jobs for lease_s (release is already possible)** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer.py:1417

*summary*: request_stop clears the local queue, and the final heartbeat carries no `holding`, so the server keeps every queued lease for lease_s (3600 s). DESIGN lists a release route as a follow-up, but since §9 the server already releases every lease older than 120 s that is not in `holding`. Sending an empty list would free them immediately.

*failure_scenario*: A client holding 200 leased-ahead jobs is stopped. Workers print SUMMARY within about a second, so no periodic heartbeat fires during the stop, and the final heartbeat has no holding. The 200 jobs stay leased for an hour: a delay mid-campaign, and in the end game reachable only through stealing.

*evidence*: volunteer.py 1099-1105: queued = [j["id"] for j in self.queue]; self.queue.clear() ... "leased jobs never started (their leases expire on the server)"
volunteer.py 1417-1418: self.api.post("/api/v2/heartbeat", {"token": self.token, "workers": self.workers, "paused": False, "boards": []}, timeout=10)
jobs.js 508/514: holding present -> reopen leases older than RELEASE_GRACE_S not in it.

*suggested_fix*: Send "holding": [] and "running": [] in the final heartbeat, and in one heartbeat right after request_stop that lists only the running ids.

*expected_gain*: A stopped client's queue returns to the pool within seconds instead of an hour.

## Verifier (CONFIRMED, low, refuted=False)
request_stop (volunteer.py:1089-1105) clears self.queue. The final heartbeat (1417-1418) posts {token, workers, paused:false, boards:[]} with no holding or running field. In jobs.js heartbeat, holdingSet is null when body.holding is not an array (508), so the release branch (514) is skipped. Every lease on the token, including the abandoned queue, is then pushed to t + lease_s (515-518). The reopen-by-omission rule exists and would release them. The incremental harm is small, though. Before the final heartbeat, those leases already ran until the last periodic heartbeat + lease_s. The final one moves that out by at most heartbeat_s (30 s, volunteer.py:41) plus the stop duration. The roughly one-hour strand is essentially the already-known 'unstarted leases not released' issue. What M22 adds is that the fix needs no new route. Also, if the stop takes long enough for a periodic heartbeat to fire, that heartbeat does carry holding = running only (1161-1163, queue empty), and it releases queued jobs older than 120 s. Two caveats on the suggested holding: []. (1) RELEASE_GRACE_S = 120 (jobs.js:41, 514) means jobs leased in the last 2 minutes before Stop are still not released and still strand for lease_s. (2) An empty list also releases jobs whose reports are still in pending or the outbox (undelivered at exit). applyReport's first-report-wins rule (jobs.js:747-749) keeps that correct, but it can cause duplicate CPU. The register() probe heartbeat (331) also lacks holding, but at start run() immediately sends a full heartbeat with holding, which releases an old queue, so that part is harmless.

*fix notes*: Final heartbeat: send running: [] and holding = the job ids of undelivered reports (pending plus outbox files). Also send one heartbeat right after request_stop with holding = running ids only. To release young (<120 s) leases too, add an explicit release: [ids] field, or the POST /api/v2/release route from DESIGN §5, that bypasses RELEASE_GRACE_S for ids the client names. Add a test_client.sh or fake_server check: after Stop with a non-empty queue, the queued ids are open on the server.
