# M63: A full DOM rebuild every 250 ms makes Copy buttons drop clicks and prevents selecting code or log text

verdict CONFIRMED, severity low, category robustness
locations: volunteer_ui.html:309 (Levels section cleared and rebuilt, log text replaced on every poll)

## Summary
On every poll the Levels section is cleared and rebuilt with new buttons, and the log text is replaced. A click whose mousedown and mouseup straddle a render goes to the container instead of the button. The 'copied' feedback is destroyed within 250 ms, and any manual text selection collapses 4 times a second, so volunteers cannot reliably copy a level code.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed. The render runs on every successful poll: line 355 `setInterval(poll, 250)`, and poll calls render right after a fast local fetch. Line 309 `const lv = $('levels'); lv.innerHTML = '';` rebuilds all three boards unconditionally through boardEl, which creates a new copy button each time (line 214 `btn.onclick = () => copyText(b.code, btn)`). The worker cards are also cleared every render (line 304 `d.innerHTML = ''`), and line 347 `$('log').textContent = (st.log || []).join('\n');` replaces the log's text node. There is no change detection for any of these, unlike lastSlots and exitOptions, which do have it. Consequences: (1) If the button is detached between mousedown and mouseup, click goes to a common or still-connected ancestor (at best #levels), never to the new button, so its onclick does not run. With a ~100 ms physical click and ~250 ms render period, a sizeable fraction of clicks is lost. Short tap-to-click presses are affected less often. (2) copyText's done() writes 'copied' into a button that is discarded at the next render, so the feedback lasts under 250 ms. The setTimeout restore then targets a detached node, which is harmless. (3) Replacing the <code> element and the <pre> text node collapses any user selection 4 times a second, so selecting a level code or log line by hand does not work in practice. This is a UX problem only: the codes are also on the public site, and retrying Copy eventually works. No effect on data or correctness.

*fix notes*: Keep per-board keys (caption + depth + code + who) and rebuild a board only when its key changes. Likewise rebuild worker cards only when their content changes, or update text nodes in place. For the log, update only when its length or last line changes, and skip the update while window.getSelection() lies inside #log. As an alternative, use one delegated click listener on #levels that reads data-code from the button, so a click on a replaced button still works.
