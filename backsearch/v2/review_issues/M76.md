# M76: The level depth on an open probe node is unbounded and becomes that row's best

verdict CONFIRMED, severity low, category robustness
locations: jobs.js:713 (best from n.level.depth with only Number.isInteger)

## Summary
For an open probe node, best is taken from n.level.depth with only a Number.isInteger check, while summary fields are range-checked. A glitching client can set an arbitrary best on a row, which then feeds exitSummary MAX(best) and the public boards.

## Source report F107 (server-ingest-routes-tools)
**The level depth on an open node is unbounded and becomes that row's best** at /Users/george/PathologyRecords/server/lib/jobs.js:713

*summary*: For an open probe node, best is taken from n.level.depth with only a Number.isInteger check. Summary fields, by contrast, are range-checked.

*failure_scenario*: A buggy client sends {depth: 100000, code: <valid level>} on an open node. best = 100000 is stored and shown as the longest level, and it heads bestOfExit and exitSummary MAX(best). Only the asynchronous 30 s solve makes v2_finish refuse; if that solve returns null, v2_finish would publish maxMoves 100000. Negative values and 1e300 are also accepted.

*evidence*: jobs.js:713 `levelBest = summary ? summary.best : (typeof n.level === 'object' && Number.isInteger(n.level.depth) ? n.level.depth : null);` vs sanitizeSummary's isInt(0, MAX_SAFE_INTEGER) checks.

*suggested_fix*: Require isInt(n.level.depth, 1, DEPTH_MAX). When a done/split node gives level.depth, also require it to equal summary.best.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed at /Users/george/PathologyRecords/server/lib/jobs.js:713: `levelBest = summary ? summary.best : (typeof n.level === 'object' && Number.isInteger(n.level.depth) ? n.level.depth : null);`. For an open node that value goes straight into the jobs row: insNode at line 790-791 stores `s ? s.best : n.levelBest`. It is also used in bestNode (line 795) and newBest (line 799), so it can become the exit's prevBest in ctx.best. bestOfExit (line 301, `ORDER BY j.best DESC`, any status) and exitSummary `MAX(best)` (line 1027) then pick it up. Number.isInteger accepts -5 and 1e300. validateLevel (lines 116-139) checks grid, caps and exit only, never the length. One correction to the finder's framing: summary fields are barely range-checked either. sanitizeSummary (line 642) checks best only against `isInt(s[k], 0, Number.MAX_SAFE_INTEGER)`, not DEPTH_MAX (4000). So a done or split node with best: 100000 and any valid level code inflates the best just as well. The open-node path adds only negative values and values above 2^53. Consequences beyond the report: (1) once an inflated best sits in ctx.best, no real later best counts as a new best, so verifyLater (v2routes.js:153) never re-solves the real champion. (2) v2_finish.js:59-61 refuses only when `v != null && v !== best`. When verified_moves is null (verifyLater timed out after VERIFY_SECONDS=30, or failed), it prints '(not re-solved yet)' and still publishes maxMoves = best. addProof (db.js:664) only refuses an understated maximum, never an overstated one. Only a buggy client can trigger this: the real client passes an int parsed from the worker's LEVEL line (volunteer.py:793-798). Snapshot check: every row with verified_moves has verified_moves == best (0 disagreements). The per-exit maxima 127/149/112/138/115/80 were all re-solved, so campaign #1 is unaffected. Stays low.

*fix notes*: In parseTree, require isInt(n.level.depth, 1, DEPTH_MAX) for a level on an open node. In sanitizeSummary, bound best (and valid) by DEPTH_MAX. When a done or split node has both summary.best and level.depth, reject the node if they differ. In v2_finish, refuse to publish an exit whose champion has verified_moves == null unless an explicit --allow-unverified flag is given, and never publish maxMoves that differs from the re-solved length. Add gate tests: open node with depth -1, 1e300 or 100000, and a done node with best > DEPTH_MAX, all expecting 400.
