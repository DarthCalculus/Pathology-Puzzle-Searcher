# M55: The global-best board never renders with the real server: level codes use newlines, but the UI regex only accepts '/'

verdict CONFIRMED, severity medium, category bug
locations: volunteer_ui.html:185 (boardText() accepts only '/'-separated rows); server stores and returns level codes joined with '\n'

## Summary
The real server returns level codes joined with '\n', so the 'best known globally' board, an owner-required §8.3 item, always shows 'no level yet for this exit'. The copy button and the 'found by X on DATE' line never appear.

## Source report F60 (client-ui)
**Global-best board never renders with the real server: codes use newlines, UI regex only allows '/'** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer_ui.html:185

*summary*: boardText() accepts only '/'-separated rows. The real server stores and returns level codes joined with '\n', so the 'best known globally' board (an owner-required §8.3 item) always shows the placeholder 'no level yet for this exit'. The copy button and the 'found by X on DATE' line never appear.

*failure_scenario*: The volunteer selects exit 1 (or Any, which also picks the first exit with a best). The heartbeat's exits['1'].best = {moves:149, code:'53005\n0BFB1\n0I400\n0B8G0\n00000', by, at}. The caption reads 'best known globally, exit 1 · depth 149' but the board reads 'no level yet for this exit', with no code and no attribution. The panel contradicts itself and the record level cannot be copied from it. test_client.sh does not catch this because fake_server.py echoes the client's '/' codes.

*evidence*: volunteer_ui.html:185 `if (!/^[0-9A-Z?]+(\/[0-9A-Z?]+)*$/.test(s)) return null;` and :315 `empty: st.exits ? 'no level yet for this exit' : 'waiting for the server'`. The attribution line is only added inside `if (txt)` (:208-210). Server jobs.js:138 `return { ok: true, code: parsed.grid.join('\n'), ...}`, jobs.js:558 `best: e.best_level ? { moves: e.best_level.moves, code: e.best_level.code, ...}`. Snapshot: `replace(level_code, char(10), '|')` for exit 1 gives `53005|0BFB1|0I400|0B8G0|00000`, and `count(*) where level_code like '%/%'` = 0.

*suggested_fix*: In boardText, split on /[\/\n]+/ as collective.js does (`String(code).trim().split(/[\/\n]+/)`), validate each row, and keep the original string for the copy button (or normalise it to one documented format). Make fake_server.py normalise codes to '\n' like the real server, and add a test_client check that the global board renders a code.

## Verifier (CONFIRMED, medium, refuted=False)
I read the code and checked the snapshot. The bug is real.

1. Server normalises every code to newlines. jobs.js:121 splits the text on `/[\/\n]+/` and joins with '\n'. Line 138 returns `code: parsed.grid.join('\n')`, and that normalised code is what gets stored in level_code (via v.code at :712 and first.levelCode at :783). The heartbeat then passes it through unchanged: jobs.js:558 `best: e.best_level ? { moves, code: e.best_level.code, by, at }`, where best_level comes from bestOfExit (:907).

2. Snapshot confirms it. 42,134 jobs have a newline in level_code and 0 have '/'. The exit 1 best is 149, `53005|0BFB1|0I400|0B8G0|00000` with char(10) replaced by '|'.

3. The client does not transform it. volunteer.py:1189-1193 stores res['exits'] as-is in self.exits, and :1333 forwards it to the panel state.

4. The UI rejects it. volunteer_ui.html:185 `if (!/^[0-9A-Z?]+(\/[0-9A-Z?]+)*$/.test(s)) return null;` has no m flag, and '\n' is neither in the class nor '/', so any multi-row newline code fails. boardEl (:207) then gets txt = null and takes the placeholder branch. Line 315 supplies `empty: st.exits ? 'no level yet for this exit' : ...`. The attribution line (opts.who, :209) and the code/copy block (:211-215) sit inside `if (txt)`, so neither appears. The caption at :203 still prints 'best known globally, exit 1 · depth 149', because gb.depth = g.moves is set. So the panel contradicts itself, as the report says.

5. Local boards are unaffected. The best-last-second, best-last-hour and current-node boards take codes from the worker's LEVEL/status output (backsearch.c:5843 level_code_text), which uses '/'. That is why only the global board is broken, and why test_client.sh and fake_server.py never caught it: fake_server.py:374 echoes the client's '/' code. test_client.sh has no check on the global board, and DESIGN.md:328 lists 'best known globally for the selected exit' as a required panel item.

Severity: medium, and I agree with the finder. This is display only. It cannot affect search correctness, the published result, or campaign data. But a required panel item is broken for every volunteer for the whole campaign, and the record level cannot be copied from the panel.

*fix notes*: 1. volunteer_ui.html boardText(): accept both separators, e.g. `const rows = String(code||'').trim().split(/[\/\n]+/).filter(Boolean); if (!rows.length || !rows.every(r => /^[0-9A-Z?]+$/.test(r))) return null; return rows.join('\n');`. This matches collective.js and jobs.js:121.
2. For the copy button and the displayed code, pick one documented format, most likely the '/' form the site accepts on paste. Something like `b.code.replace(/\n/g,'/')` keeps the <code> element on one line.
3. Optionally have jobs.js:558 send a '/'-joined copy so heartbeat consumers never see raw newlines. If you do, document the format in DESIGN §8.
4. Make fake_server.py store codes the way jobs.js:121/138 does (split on /[\/\n]+/, join with '\n') so the fake matches the real server.
5. Add a test_client.sh check: after a job reports a level, fetch the panel state and assert exits[e].best.code parses through the same boardText logic. Better, run a small node/python check of the regex against a newline code.
