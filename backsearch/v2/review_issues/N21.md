## Verifier (CONFIRMED, low, refuted=False)
Checked the code. At backsearch.c:1839-1845, flush_surrogate_pending prunes only on `x >= 0 || x == -2 || x == -4`. A -3 falls through to the accept block at 1847-1862, which sets g_best_depth, g_best_state and the overall best, then q_push(&ns) at 1877. try_successor_x at 2218 prunes on `|| x == -3`. -3 is a real solver return: sokoban_bfs.c:1260/1271 and 1749/1762 return it on probe failure, and shortcut_check passes rc through.

One correction: the flush path does NOT increment g_accepted_valid. Only backsearch.c:2244 does, so the valid-level count is not inflated. Only best is affected, and the server re-verifies the best level (jobs.js setVerified).

Reachability is narrower than stated. The client does pass extra unfiltered (volunteer.py:417-425), and the server checks only length (jobs.js:347-348). But reaching this path needs three things at once: --nn-surrogate-model in the campaign's extra, a build linked against torch (build_pgo.sh links torch only when `import torch` works), and the model file present at that path on the volunteer's machine. Otherwise nn_surrogate_load fails, the stub returns 0, and the worker exits 1 with 'fatal: failed to load NN surrogate' (backsearch.c:5465-5468). Every job then fails fast instead of silently accepting.

Two consequences, if the path were ever active in a campaign, are far worse than the -3 inconsistency:
1. do_prune (1832-1837) drops states on an NN prediction alone, which is unsound for an exhaustive search.
2. The flush path q_pushes ns without the edge token. try_successor_x adds it with path_push at 2250. The flush path also skips adjflags, the ptab export and g_win_depth. A split therefore hands back REMAINING seed paths that name the parent, not the child, so those subtrees are lost or re-run.

The -3 mismatch is real but minor. It stays low because only the owner's own campaign misconfiguration can reach it.

*fix notes*: 1. Make the worker refuse --nn-surrogate-model (and the other --nn-*, beam and rollout modes) together with --seed-path or --split-after. That kills the whole class in campaign mode, which matters more than the -3 branch.
2. Add the extra-flag whitelist on the client and on the server (jobs.js at campaign creation), not only on the client.
3. Route both 1840 and 2218 through one classify(x) helper so they cannot drift.
4. If the surrogate path is kept for experiments, give it the missing path_push, adjflags and export steps.
