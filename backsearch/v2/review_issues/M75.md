# M75: Name sanitisation lets bidi, zero-width and C1 characters through, and counts length in different units from the client

verdict CONFIRMED, severity low, category security
locations: jobs.js:84 (cleanName strips only C0 and DEL; length in UTF-16 units vs client's 40 code points)

## Summary
cleanName removes only C0 controls and DEL, so bidi overrides, zero-width and C1 characters can spoof or garble names on the public boards. It counts length in UTF-16 units, while the client cuts names at 40 code points. HTML injection is not possible, because every page escapes names.

## Source report F106 (server-ingest-routes-tools)
**Name sanitisation lets bidi, zero-width and C1 characters through, and length units differ from the client** at /Users/george/PathologyRecords/server/lib/jobs.js:84

*summary*: cleanName removes only C0 controls and DEL. It counts length in UTF-16 units, while the client cuts names at 40 code points. HTML injection is not possible, because every page escapes names.

*failure_scenario*: 'Zach​' displays as 'Zach' but is grouped as a separate contributor. A name ending in U+202E reverses the rest of the contributors line, because names are joined into one paragraph. A 30-emoji name passes the client's [:40] but is 60 UTF-16 units, so the server returns 400 and the client exits with 'Registration refused'.

*evidence*: jobs.js:84 `Array.from(n).filter(ch => ch.charCodeAt(0) >= 32 && ch.charCodeAt(0) !== 127)`; 85 `s.length > NAME_MAX`. volunteer.py:362 `name = name.strip()[:40]`. hunt.js:128 joins names with ' · '.

*suggested_fix*: Strip \p{Cc}, \p{Cf} and lone surrogates, NFC-normalise, count code points on both sides, and wrap names in <bdi>.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed. The filter at jobs.js:84 is `Array.from(n).filter(ch => ch.charCodeAt(0) >= 32 && ch.charCodeAt(0) !== 127)`, followed by `.replace(/\s+/g,' ')`. C1 controls (U+0080-009F), bidi controls (U+202A-202E, U+2066-2069), U+200B/200C/200D and lone surrogates all get through: they are >= 32, and JS \s does not match them. Line 85 compares `s.length > NAME_MAX`, which counts UTF-16 code units. The client (volunteer.py:365, not 362) does `name = name.strip()[:40]`, which counts Python code points. A name of 21-40 astral characters (emoji) passes the client and fails the server. The client then prints 'Registration refused: ...name must be 1..40 characters' and exits (volunteer.py:373-375). The error is clear, but the user did type 40 or fewer characters. Names are grouped by exact string (contributors `GROUP BY cl.name`, jobs.js:312/879). hunt.js:128 joins every name into one <p>, and the <b> elements have unicode-bidi: normal. So an unterminated U+202E reorders the rest of that paragraph, and 'Zach' plus a zero-width space shows as a second 'Zach'. All pages escape names (esc()), so there is no HTML injection. Volunteers are trusted, and a >20-emoji name is rare. Cosmetic only; low.

*fix notes*: In cleanName, NFC-normalise and strip \p{Cc}, \p{Cf} (bidi and zero-width) and lone surrogates, e.g. with a /[\p{Cc}\p{Cf}]/gu regex or an explicit code-point filter. Count length as Array.from(s).length. Match the client to it (strip the same classes, count code points, or have the client trust the server's cleaned name). Wrap displayed names in <bdi> (or apply CSS unicode-bidi: isolate) on hunt.js, collective.js and campaigns.js.
