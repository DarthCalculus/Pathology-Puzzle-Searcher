# M13: The worker update and fallback build instructions produce a binary the client does not use or rejects

verdict CONFIRMED, severity medium, category docs
locations: volunteer.py:401 (stale-hash message 'git pull && ./build_pgo.sh'); v2/README.md (same advice); build_pgo.sh (writes ./backsearch_worker, links libtorch if torch is installed); VOLUNTEERS.md:35 (plain cc fallback without -DSRC_HASH_STR)

## Summary
When the worker hash is stale, the client says to run `git pull && ./build_pgo.sh`. That writes ./backsearch_worker, while the client's default binary is ./backsearch_worker_nt, so the stale binary is still used and refused again. The plain `cc -O3 -o backsearch_worker_nt ...` fallback in VOLUNTEERS.md omits -DSRC_HASH_STR, so the worker prints an empty hash and the client exits calling it 'too old'. That fallback is also not PGO-optimised.

## Source report F34 (worker-io-cli-memory)
**Client's update command rebuilds ./backsearch_worker, but the client runs ./backsearch_worker_nt; the documented plain-cc fallback always gets rejected** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer.py:401

*summary*: When the worker hash is stale or missing, volunteer.py and v2/README.md tell volunteers to run `git pull && ./build_pgo.sh`. That writes ./backsearch_worker (and links libtorch if torch is installed), while the client's default binary is ./backsearch_worker_nt, so the stale binary is still used and refused again. Separately, the fallback in VOLUNTEERS.md (`cc -O3 -o backsearch_worker_nt ...`) compiles without -DSRC_HASH_STR, so the worker prints an empty hash and the client calls it 'too old'.

*failure_scenario*: The owner whitelists a new hash after a worker fix. Each volunteer's client refuses with 'Update and rebuild ... git pull && ./build_pgo.sh'. The volunteer runs it, restarts, and gets the same refusal because backsearch_worker_nt was never rebuilt. They are locked out until they find `-o backsearch_worker_nt`. A volunteer whose PGO build fails and uses the documented plain build gets 'The worker did not print an SRC_HASH line ... It is too old', which is wrong advice.

*evidence*: volunteer.py:400-401 `"Accepted: %s\nUpdate and rebuild in the backsearch directory:\n" "    git pull && ./build_pgo.sh\n..."` and 293-294 `update the checkout and rebuild: git pull && ./build_pgo.sh`; 1535 `ap.add_argument("--worker", default=os.path.join(".", "backsearch_worker_nt"), ...)`. build_pgo.sh:25 `OUT=./backsearch_worker`. v2/README.md:37 `you will be told to git pull && ./build_pgo.sh`. VOLUNTEERS.md:35 `cc -O3 -o backsearch_worker_nt backsearch.c sokoban_bfs.c nn_stub.c -lz -lm`, with backsearch.c:500-501 `#ifndef SRC_HASH_STR #define SRC_HASH_STR ""` and the client's HEX_RE `^[0-9a-fA-F]{8,128}$`.

*suggested_fix*: Print the exact command from the client, built from args.worker: `./build_pgo.sh -o backsearch_worker_nt --no-torch`. Alternatively make that build_pgo.sh's default output. Replace the plain-cc fallback with a build that computes SRC_HASH (build_pgo.sh already falls back to plain -O3 with the hash when llvm-profdata is missing), and make the empty-hash message say the binary was built without a source hash.

*expected_gain*: Volunteers can recover without help after every hash rollover.

## Source report F167 (algo-worker)
**VOLUNTEERS.md fallback build produces a worker the client rejects** at /Users/george/Documents/Claude Projects/project45/backsearch/VOLUNTEERS.md:35

*summary*: The documented plain build has no -DSRC_HASH_STR, so the worker prints an empty SRC_HASH. volunteer.py then exits with 'It is too old; update the checkout and rebuild'. The fallback is also not PGO-optimised.

*failure_scenario*: A volunteer whose build_pgo.sh fails (for example no llvm-profdata on Linux clang) follows the documented fallback, cannot start, and is told the checkout is 'too old'.

*evidence*: VOLUNTEERS.md:32-36 'If it fails, the plain build works too: cc -O3 -o backsearch_worker_nt backsearch.c sokoban_bfs.c nn_stub.c -lz -lm'; backsearch.c:500-501 '#ifndef SRC_HASH_STR / #define SRC_HASH_STR ""'; volunteer.py:291-294 requires HEX_RE (8-128 hex chars), otherwise 'It is too old; update the checkout and rebuild'.

*suggested_fix*: Add -DSRC_HASH_STR=\"$(cat backsearch.c sokoban_bfs.c sokoban_bfs.h | shasum -a 256 | cut -c1-64)\" to the fallback command, or have build_pgo.sh's no-PGO path used instead. Make the client message say 'built without SRC_HASH' when the value is empty.

*expected_gain*: No speed effect; volunteers who follow the fallback can start.

## Verifier (CONFIRMED, medium, refuted=False)

The client defaults to `--worker ./backsearch_worker_nt` (volunteer.py:1535).
