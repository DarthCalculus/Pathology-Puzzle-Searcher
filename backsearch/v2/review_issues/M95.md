verdict CONFIRMED, severity low, category test-gap

## Summary
The heartbeat, lease, batch-send and window-deadline logic and wake detection all use time.time(). A backward clock step suppresses heartbeats, leases and sends for the step's length, and a forward step above 2x lease_s triggers handle_wake. Server lease maths uses server time, so that side is safe. On WSL, the documented Windows path, a CRLF checkout changes SRC_HASH (fails safe by refusing), and /mnt/c filemode noise makes check_dirty refuse to start. None of this is tested.

## Verifier (CONFIRMED, low, refuted=False)
The code facts hold. volunteer.py uses time.time() for every interval and deadline: the heartbeat interval (1379), the lease throttle (463), the no_jobs_until check (461), the sender batch interval (892), the window deadline (566-567, with `max(1.0, deadline - now)` passed as --split-after at 587), wake detection (1375-1378), the stop-signal and kill timers (1390-1397), ui_close (1399), and job durations (686). The file never uses time.monotonic. Tests have no clock-step coverage. A backward step of X suppresses heartbeats, lease requests and batch sends for about X s, and stretches the current window by X. If X exceeds about lease_s, the server (which uses its own clock) sweeps the leases. One consequence not in the report: dur = time.time() - start can go negative and feeds job_durations. mean_job_s clamps at 0.05 (436-437), so a large negative sample can drive per_worker = ceil(300/0.05) up to the lease_cap of 200 jobs, and the client hoards jobs until 20 new samples wash it out. A forward step above 2*lease_s only triggers handle_wake, which SIGSTOPs the workers, heartbeats, finds all leases still valid (server time is unaffected) and resumes them. That costs a short pause and is harmless. The worker itself uses CLOCK_MONOTONIC (backsearch.c:1624 and others), so runs already in progress are unaffected. Realistic triggers are rare. NTP normally slews rather than steps. WSL2's typical post-sleep correction is a forward step that matches real suspended time, where handle_wake is the right response. Backward steps of about an hour need a manual change or a bad VM clock. The WSL points are partly overstated. CRLF only occurs when a Windows-git checkout is used from WSL; VOLUNTEERS.md:21 says to work inside WSL, where Linux git does not convert line endings. It fails safe anyway, through check_dirty or the hash refusal. Filemode noise on /mnt/c is unlikely, because git sets core.fileMode=false at clone time when chmod does not stick. Caveat on the suggested fix: time.monotonic() excludes suspend on Linux (CLOCK_MONOTONIC) and on macOS, so switching the wake detector to it would disable sleep detection entirely.

*fix notes*: Use time.monotonic() for intervals, throttles, window deadlines and durations, and clamp durations at >= 0. For wake detection, compare the two clocks: wake if (wall_gap - mono_gap) > threshold. You can also use CLOCK_BOOTTIME where it is available, but not plain monotonic. Unit-test by monkeypatching time.time and time.monotonic with a scripted clock that steps back 4000 s. Assert that heartbeats continue on schedule and that lease_want stays bounded.
