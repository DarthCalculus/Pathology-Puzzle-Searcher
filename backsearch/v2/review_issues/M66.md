# M66: The last-hour and last-second level boards miss levels from runs shorter than one STATUS interval

verdict CONFIRMED, severity low, category bug
locations: volunteer.py:875 (hour_best fed only from STATUS 'win' samples); worker prints STATUS every >= 250 ms and no final STATUS; best_per_exit (from LEVEL) not displayed

## Summary
hour_best is fed only from STATUS 'win' samples. The worker prints STATUS at most every 250 ms and never prints a final one, so levels found in short runs or in a run's last moments reach only best_per_exit (via LEVEL), which the panel never displays.

## Source report F72 (client-ui)

*summary*: hour_best is fed only from STATUS 'win' samples. The worker prints STATUS every 250 ms or more and never prints a final one, so levels found in short runs or in a run's last moments reach only best_per_exit (via LEVEL), which the panel never displays.

*failure_scenario*: Many runs finish under 250 ms (in the snapshot, 131,459 of 167,766 job rows have elapsed_s < 0.25 and 18,738 of those hold a level). A deep level found in such a child or absorb probe never appears under 'best here, last hour', which then shows a shallower level than this machine actually found in the hour.

*evidence*: volunteer.py:871-875 `if win: ... self._hour_best_add(now, win["depth"], win["code"], ...)` is the only caller; _note_level :721-726 updates only self.best_per_exit. backsearch.c:4651 `if (g_status_every_ms > 0 && el - last_status_s >= g_status_every_ms / 1000.0) { print_status(&s); ...}` runs inside the DFS loop only.

*suggested_fix*: Also call _hour_best_add(time.time(), level['depth'], level['code'], job['exit']) from _note_level. Optionally show best_per_exit as 'best on this machine this session'.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed.
- _hour_best_add is called only from _on_status (volunteer.py:875), which is fed by STATUS 'win' samples.
- _note_level (720-726) updates only best_per_exit. state() exports best_per_exit (1322), but volunteer_ui.html renders only best_second and best_hour (310-311).
- In the worker, print_status runs only inside the DFS loop, gated on `(++iter & 1023) == 0` and `el - last_status_s >= 0.25` (backsearch.c:4646-4651), with last_status_s = 0 at run start (4378). There is no STATUS after the loop ends (4653-4656), and g_win_depth, which accumulates since the last STATUS (2244), is dropped at the end of the run.

As a result, any run under 0.25 s never feeds the hour board, and a level found in the last window of a longer run is also missed. The snapshot matches: 131,459 of 167,766 rows have elapsed_s < 0.25, and 18,738 of those hold a level. The per-exit champions of campaign #1 came from long runs (41-1788 s), so this has mostly hidden sub-champion levels.

The damage is limited to the local panel. boards() (1148-1158) sends only cur/best depth, and the server computes public bests from reports. Severity is low and cosmetic.

*fix notes*: In _note_level, under the lock it already takes, also call self._hour_best_add(time.time(), level['depth'], level['code'], job['exit']). Optionally, in the worker, print one final STATUS after the DFS loop when g_status_every_ms > 0 and g_win_depth > 0. Changing the worker changes SRC_HASH, so leave that for a planned rebuild. Optionally show best_per_exit as 'best on this machine this session'.
