# M64: /state calls worker_argv_base(), which raises SystemExit in the HTTP thread if the binary is missing

verdict CONFIRMED, severity low, category robustness
locations: volunteer.py:1348 (state() rebuilds the worker path every poll via worker_argv_base -> sys.exit)

## Summary
state() rebuilds the worker path on every poll. If the binary is missing (for example, mid-rebuild), worker_argv_base writes an error and raises SystemExit inside the handler thread. The connection closes with no response, and the panel wrongly declares the client dead.

## Source report F70 (client-ui)
**/state calls worker_argv_base(), which sys.exit()s in the HTTP thread if the binary is missing** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/volunteer.py:1348

*summary*: state() rebuilds the worker path on every poll. If the binary is missing, worker_argv_base writes an error and raises SystemExit inside the handler thread. The connection is dropped with no response, and the panel wrongly declares the client dead.

*failure_scenario*: While the client runs, the volunteer rebuilds or cleans the build so that backsearch_worker_nt briefly or permanently does not exist. Every /state then fails, stderr gets 'Worker binary not found' 4 times a second, and after 2 s the panel says 'The client is not answering (stopped or exited). You can close this tab.' while the workers are still running. Closing the tab then stops the client. The same function in run_worker kills the slot thread with slot.job still set, so the heartbeat keeps renewing that job's lease until the client exits.

*evidence*: volunteer.py:1348 `"worker_path": " ".join(self.worker_argv_base()),`; :274-277 `if path is None: sys.stderr.write("Worker binary not found: ..."); sys.exit(2)`; worker_argv :421 `return self.worker_argv_base() + [...]`.

*suggested_fix*: Resolve the worker path once at startup and cache it. Never call sys.exit outside the main thread. In run_worker, treat a missing binary as a failed run.

## Verifier (CONFIRMED, low, refuted=False)
state() (volunteer.py:1348) calls self.worker_argv_base() on every /state poll, and the UI polls every 250 ms (volunteer_ui.html:355). worker_argv_base (266-280) runs os.path.isfile on each poll and, if the file is missing, writes to stderr and calls sys.exit(2). The /state handler (1469-1470, `self._send(200, vol.state())`) has no try block. socketserver's ThreadingMixIn.process_request_thread catches only Exception, so SystemExit escapes: the thread ends silently (threading.excepthook ignores SystemExit), and the finally block shuts the socket with no response. `with self.lock` releases the lock on the way out, so there is no deadlock. After 8 consecutive fetch failures (2 s), the UI shows 'The client is not answering (stopped or exited). You can close this tab.' Closing the tab triggers /close and request_stop, which is graceful but is a stop the volunteer did not intend. The slot path is worse. run_window sets slot.job before calling run_worker, and run_worker calls worker_argv at line 731 outside any try block. SystemExit then ends the slot thread with slot.job still set. _reconcile_slots is called only at start and in set_workers, so the slot is never revived. heartbeat() (1161-1163) keeps listing that job in running/holding, so its lease is renewed while the client lives. If the binary stays missing, every slot dies at its next run, and the client becomes a heartbeating zombie that holds its running jobs and its whole lease-ahead queue. The UI says the client is dead; with --no-ui nothing is visible at all. This is not a permanent stall: endgame stealing and the post-exit lease expiry recover the jobs, and nothing is lost (the server re-issues the whole job). The trigger (deleting or relinking the binary while the client runs) is unusual. build_pgo.sh writes $OUT only at the final link (lines 93 and 117), so a normal rebuild leaves a gap of milliseconds, not minutes. Low is the right rating.

*fix notes*: Resolve the worker path once at startup (main already calls worker_argv_base at line 1551), cache it in self.worker_base, and use the cached value in state() and worker_argv. Never call sys.exit off the main thread. In run_worker, wrap argv construction and Popen so that any failure returns None, which counts as a failed run: backoff applies and slot.job is cleared through the existing res-is-None path. Wrap the /state handler in try/except BaseException and return 500 JSON.
