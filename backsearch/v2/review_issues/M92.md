**test_load can pass with every report rejected or with the server down** at /Users/george/Documents/Claude Projects/project45/backsearch/v2/test_load.py:74

*summary*: Two problems. Rows are counted as written whenever /reports returns 200, but that endpoint returns 200 with per-report errors inside. And post() catches only HTTPError, so URLError, timeouts, connection resets and non-JSON error bodies kill the client thread silently (threading's excepthook prints them) and are never added to errors. The simulation also skips the heartbeat's holding/running lists, public /status and /campaigns polling, and a campaign-sized DB.

*failure_scenario*: If a schema change makes jobs.js reject every simulated tree (all results code 400), test_load prints thousands of rows/s and 'errors: 0' and exits 0. If node crashes mid-run, every thread dies on URLError and the run also exits 0. The measured latency comes from 50k fresh roots and does not reflect campaign #1's 166,733-job DB with the steal query (LIMIT 5000 join) and 5000-id holding lists.

*evidence*: test_load.py:29-32 `except urllib.error.HTTPError as e: out = json.loads(e.read().decode() or '{}'); code = e.code` (no other except); 71-75 `c, o, d = post('/api/v2/reports', ...)` / `if c == 200: rows[0] += sum(len(r['nodes']) for r in reports)`; 63 heartbeat body `{"token", "workers", "paused", "boards"}` (no holding/running); 95 `sys.exit(1 if errors else 0)`.

*suggested_fix*: Inspect o['results'] and count each non-ok result as an error. Wrap every request in a broad except that records the error. Add holding/running to heartbeats and public-page pollers, and run against a copy of jobs_review.db.

*expected_gain*: The load test becomes a real capacity gate.

## Verifier (CONFIRMED, low, refuted=False)
Both mechanisms hold.

Rejected reports are counted as written:
- jobs.js:836-853 reports() returns `{ ok: true, results }` with per-report errors inside, so HTTP status is 200 even when every report is refused (v2routes.js:89/158 answer(res, r)).
- test_load.py:74 (`if c == 200: rows[0] += sum(len(r['nodes']) for r in reports)`) never looks at o['results'], so refused reports count as rows written and are not added to errors.
- I checked that today's synthetic trees pass parseTree: split nodes may omit a summary, done summaries carry states/valid/best, and child seeds are unique by base-12 encoding. The miscount is therefore latent, not happening now.

Other failures kill threads silently:
- post() (lines 28-31) catches only urllib.error.HTTPError.
- URLError (server down), socket timeouts, ConnectionResetError and a JSONDecodeError on a non-JSON body are all left uncaught. Each kills its client thread; threading's excepthook prints to stderr, but errors[] stays empty.
- Line 95 then exits 0. A server crash mid-run yields exit 0 with short latency lists.

Coverage gap:
- The heartbeat body at line 63 has no holding/running. So the release path (jobs.js:508-514) and the lease renewal loop over up to 5000 held ids (526-529) never run.
- running_json is never populated for the steal ranking (jobs.js:610-615).
- Nothing polls the public /status or /campaigns pages.
- The seeded DB is 50k fresh roots (test_load.sh:22), smaller than campaign #1's 166,733 jobs.

Re-rated low rather than medium. The load test is a capacity sanity tool, not a correctness gate, and gate tests cover report rejection. Campaign #1 already exercised the server at production scale, and the realistic next-campaign scale (10x16) is far below the test's default 40x32. A crash would show as tracebacks on stderr to anyone reading the output; only an automated pass/fail would be misled.

*fix notes*: For /reports, count every result with `not r.get('ok')` as an error, and add only the node counts of ok results to rows. Wrap each request in `except Exception as e: errors.append((path, type(e).__name__, str(e)[:200]))` and keep the thread alive, or make the test fail when any thread dies. Send holding (the held ids) and running in heartbeats. Add a /status and /campaigns poller. Allow running against a copy of jobs_review.db (JOBS_DATA_DIR pointing at a copied snapshot with a whitelisted test hash). Also note that 40 clients x about 14 req/min from 127.0.0.1 is close to the default V2_IP_PER_MIN of 600 (server.js:30): larger runs will hit 429 unless test_load.sh raises it as test_chaos.sh does.
