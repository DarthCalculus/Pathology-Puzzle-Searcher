## Source report F227 (r2-publish-path-and-verifier)
**Cross-size supersession uses padded walls, but the any-size view filters raw walls, so 'Any size + min walls' hides levels whose superseder fails the filter** at /Users/george/PathologyRecords/server/lib/db.js:274

*summary*: A smaller level supersedes a larger one when walls + padding >= the larger level's walls (dominatesPadded, applied at submitLevel 235-243). In the any-size search, minWalls compares raw walls and superseded rows are dropped. The superseded level is gone, and its superseder, which has fewer raw walls, is filtered out too.

*failure_scenario*: The scratch records snapshot has 576 such pairs. Example: verified #941 (7x9, 221 moves, 30 walls) is superseded by #1011 (6x6, 9 walls). 'Any size, min walls 30' (default tiers) shows a record of 39 moves while a 221-move verified level with 30 walls exists. Each new champion adds more such pairs (a 5x5 champion supersedes 5x6/6x6 levels with up to 5-11 more walls).

*evidence*: db.js:274: if (!target && f.minWalls != null) { cond.push('walls >= ?'); args.push(f.minWalls); }
db.js:158: if (paddedWalls(a, b.rows, b.cols) < b.walls) return false;
sqlite (scratch copy): l=941 7x9 221 moves 30 walls, superseded_by 1011 6x6 9 walls; max active verified/claimed moves with walls>=30 = 39.

*suggested_fix*: For an any-size query with minWalls, also return superseded levels whose superseder fails the filter, or compute that filter's Pareto front on the fly. Alternatively, supersede across sizes only in the size-specific views.

## Verifier (CONFIRMED, low, refuted=False)
Confirmed from code and data. When a candidate fits inside a bigger level, submitLevel supersedes that level (db.js:235-243) using dominatesPadded (db.js:155-162). dominatesPadded compares padded walls: 'if (paddedWalls(a, b.rows, b.cols) < b.walls) return false;' at db.js:158. searchLevels excludes superseded rows ('superseded = 0', line 263). With no target size, it filters raw walls: 'if (!target && f.minWalls != null) { cond.push('walls >= ?') ... }' at db.js:274. server.js:97-111 allows minWalls without a size (only exit requires a size), and app.js:400 sends minWalls whenever the box is ticked. In the scratch copy review/records_copy.db: level 941 (7x9, 221 moves, 30 walls, verified, superseded=1) has superseded_by 1011 (6x6, 227 moves, 9 walls). The largest active verified/claimed move count with walls>=30 is 39. There are 576 cross-size superseded pairs whose superseder has fewer raw walls (416 with the superseder still active). So 'Any size + min walls 30' shows 39 as the record, while a verified 221-move level with 30 walls exists. The same pattern exists, latent (0 cases in the snapshot), for noExitPush. dominatesPadded and dominates check only pushesOverExit and ignore pushes_known, but the view filters 'pushes_over_exit = 0 AND pushes_known = 1' (db.js:275). A superseder with unknown pushes could therefore hide a known-no-exit-push level from that view too. This is a wrong display on the public site only. It does not touch campaign correctness or proofs, so low.

*fix notes*: In searchLevels, when there is no target size and a filter (minWalls, noExitPush) is not preserved by dominance, also include superseded levels whose superseder fails that filter. Alternatively, recompute the Pareto front of the filtered set on the fly instead of relying on the superseded flag. Make dominates/dominatesPadded also require !(b.pushesKnown && !a.pushesKnown), or apply the same fallback for noExitPush.
