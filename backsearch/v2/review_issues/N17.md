*failure_scenario*: A tester builds with 'cc -DHP64_SIZE=512 ...' to exercise finding 1. The source's own '#define HP64_SIZE (1 << 20)' wins after a redefinition warning, and the test silently exercises nothing. Or someone adds guards and builds with tiny tables for local tests, then points a volunteer.py at the live server with that binary. Its SRC_HASH matches the campaign whitelist, and it reports runs with many unresolved candidates, or path_overflow failures, as trusted results.

*suggested_fix*: - Wrap each of these macros in #ifndef.
- Define SRC_HASH as sha256(sources || '\0' || sorted list of every -D knob override). build_pgo.sh computes it and passes the knobs; any other build recipe must use the same rule.
- The worker prints its effective knob values in --version (a KNOBS line).
- Amend DESIGN §2 ('the hash is of the source') to 'source plus declared knob overrides'.
- One commit, before any acceptance run. It changes SRC_HASH once.

## Verifier (CONFIRMED, low, refuted=False)
The code is as described:
- These macros are plain #defines with no #ifndef guard: HT_PROBE_LIMIT (sokoban_bfs.c:431), HTP_SIZE (932), HP64_SIZE (939), HTP_SMALL_LG2 (980), REF_LG2 (1379), MS_LG2 (1808), MS_ARENA (1811), and PATH_TOK_MAX (backsearch.c:227).
- Only HASH_LG2, SHALLOW_LG2 and RECENT_LG2 (855/884/887) are guarded.
- build_pgo.sh:41 hashes the source text only.

Passing -D for an unguarded macro gives a 'macro redefined' warning, and the source's value wins. So knob tests test nothing unless someone reads the warning.

The provenance gap exists today, not only after guards are added. These existing knobs all build a behaviorally different solver under the same SRC_HASH:
- #ifdef/#ifndef knobs: HOLEBOUND (1559), NO_ASTAR (1548/1705), MS_NO_DOM (1944/2052), MAND_OLD (878), REF_CHECK, BULK_CHECK.
- The already-guarded dedup sizes.

build_pgo.sh also expands $CC unquoted (`$CC $CFLAGS ...`), so `CC="cc -DHOLEBOUND" ./build_pgo.sh` produces such a variant carrying the production hash, which the server accepts. A plain manual cc build without -DSRC_HASH_STR prints an empty hash (backsearch.c:500-502) and is refused, so the gap needs build_pgo.sh with CC overridden, or a copied hash.

Re-rated from medium to low. Campaign results are affected only if a trusted person deliberately points a non-standard build at the live server. Otherwise the gap only blocks the knob tests other findings propose. It should still land before any acceptance run.

*fix notes*: In one commit:
1. Add #ifndef guards for the listed macros.
2. Define SRC_HASH over the sources plus a canonical, sorted list of every -D knob. Have build_pgo.sh compute it, and add a KNOBS line to --version.
3. Make build_pgo.sh reject flags smuggled in through CC (or fold them into the hash).
4. Update DESIGN §2's 'hash is of the source' wording.
